# 字数核验规范（唯一出处）

本文件是 shenlun-judge 处理"字数"问题的**唯一权威口径**：字数怎么数、怎么判定合规、
示例答案怎么保证不超限、报告里怎么写。其他文件只做指引，不另立口径。

工具：`scripts/count_chars.py`（本 skill 自带，Python 3 标准库，无第三方依赖）。

---

## 0. 要治的问题（根因）

**核心毛病：示例答案（含参考答案、满分答案、范文）字数超标，且标注的字数不实。**

已核实的事故：

> 2020 河南乡镇卷第一题（要求"不超过 300 字"），报告写"**参考作答要点（供对照，约 290 字）**"，
> 脚本实测 **384 字**（含标点）——**超上限 84 字，占比 128%**。标称值与实测值差 94 字。

成因有三个，都要在本文件里堵住：

1. **凭语感估数**：模型目测中文串长度误差可达 20% 以上，"约 290 字"是估出来的，不是数出来的；
2. **写答案时不带字数约束**：先把采分点写全、写完就交，没人回头核对上限；
3. **口径混乱**：汉字数、字符数、含标点数混用（历史报告里同时出现过"866 汉字""981 字符"
   两种写法），读者无法判断到底达没达标。

> 说明：用户作答字数的统计此前基本可用（用脚本复核多份历史报告，作答字数与报告一致）。
> 本文件的修正重点在**示例答案一侧**，不对历史报告中的用户作答字数作追溯性否定。

---

## 1. 两个口径必须分开：评分口径 ≠ 统计口径

| | **评分口径**（扣不扣分） | **统计口径**（报不报数） |
|---|---|---|
| 依据 | 阅卷人不数字数，只看答题卡格子占用与内容完整度 | 逐字符统计，精确到 1 字 |
| 结论 | 字数不单独扣分；"没写完"体现在内容/结构维度 | 必须给出"X 字 / 上限 N 字 / 占比 %" |
| 出处 | `essay-judging.md` 第 3 步"字数判断" | 本文件 + `scripts/count_chars.py` |

- 旧规则（不因实际字数机械倒扣）**继续有效**，本文件不改变任何评分尺度。
- **禁止的错误推理**："反正字数不扣分，所以示例答案写多长都行"——示例答案是给用户**模仿**的，
  它超限等于教用户在考场上超限，比报错数字更严重。
- **同样禁止**：因为要报精确字数，就在评分里加一条"超 1 字扣 0.5 分"——那是另一头的错。

## 2. 计数口径（答题卡口径 = 主口径）

**计入（每字符占答题卡一格）**：

- 汉字；
- 标点（，。、；：""''！？——……《》等，全角半角各计 1）；
- 数字与字母（2024、GDP、5G 的每个字符各计 1）；
- 序号（"1."、"（2）"、"一、"、"一是"）；
- 标题、称呼、落款、日期。

**不计入**：

- 空格、制表符、换行（在格子之外）；
- **助手转写/排版时添加的 markdown 标记**：`**` `` ` `` `#` `>` `|` `~`、列表符 `- `/`* `、
  代码围栏 ```` ``` ````——这些不是考生写的，脚本会自动净化；
- **以 `【说明】`「【批注】」「【备注】」「【转写说明】」「【作答说明】」开头的说明段**
  （从该行到空行或文末）：这是背景说明，不是答题内容，**不占答题卡格子**；
  脚本剔除后会输出"[提示] 已剔除 N 段【说明】类说明文字"。
  行内的 `【作答】`「【答案】」「（转写存疑）」「（此处略）」「（约 X 字）」等标注同样不计入；
- 报告自身的栏目名与标题行（如"【作答】""【满分答案】""（此处为报告批注）"）。

**报告用语统一为"X 字（含标点）"**，不得只写"X 字"造成口径歧义；需要解释构成时附辅助口径
（纯汉字数、去行首序号数）。

## 3. 先识别题干的字数要求（识别错，后面全错）

| 题干表述 | 类型 | 判定基准 | **示例答案目标区** |
|---|---|---|---|
| 不超过 300 字 / 300 字以内 / 限 300 字 | 硬上限 | > 300 即超限 | **255–285（85%–95%）** |
| 300 字左右 / 约 300 字 | 弹性 ±10% | 270–330 为达标 | 270–320 |
| 1000—1200 字 | 区间 | < 1000 或 > 1200 均不合要求 | 1050–1150 |
| 不少于 800 字 / 800 字以上 | 下限 | < 800 偏少 | 850–1000 |
| 总字数 1000 字左右（大作文） | 弹性 ±10% | 900–1100 达标 | 950–1050 |

> **依据层级**：题干给出的字数限制本身是**官方公开的作答要求（L1）**，必须严格遵守；
> 而表中"示例答案目标区（85%–95%）"是**本 skill 的训练建议（L3 经验口径）**——
> 报告中要写"按本 skill 训练口径控制在 85%–95%"，**不得写成"官方要求字数控制在 85%–95%"**。

- 题干未给字数要求 → 只报统计值，不判定合规性，并提示"题干未给字数要求"。
- **大作文的标题是否计入**：题干说"总字数"含标题；题干另说"正文"则不含标题。
  报告一律给分解：`含标题 X 字（其中正文 Y 字）`。
- 官方从未公布"超 X 字扣 Y 分"的罚则，所以字数只决定**训练建议**，不决定分数（见 §1）。

## 4. 标准动作

### 4.1 示例答案 / 满分答案 / 范文（必做，硬约束）

**示例答案必须 ≤ 题目上限且落在上限的 85%–95%**（区间题按 §3 目标区）。
流程：**写要点 → 写成纯文本 → 跑脚本 → 不达标就压缩 → 再跑脚本 → 达标才输出**（详见 §5）。

### 4.2 用户作答（轻量核验）

- **作答来源**：优先用对话里贴出的作答；否则到工作区 **`作答记录/{省份}/`** 取对应文件
  （匹配与命名约定见 `SKILL.md` 第三节第 1 步；**`作答记录/` 只收 md/txt**，
  图片请用户先自行转文本）。
- 用一条命令数一次即可，套卷可用 `--split` 一次切块统计全卷，无需逐题落盘：

  ```bash
  python .dsh/skills/shenlun-judge/scripts/count_chars.py 作答记录/河南/2020河南乡镇.txt --split --limits 300,200,300,500,500 --label "2020河南乡镇"
  ```

  - `--split` 按"第X大题/第X题"切块；**文件名与题号对不上时先人工核对**，不要硬套 `--limits`。
  - 分题存放（`2022河南乡镇-第3题.md`）时逐文件统计即可，不必用 `--split`。
  - docx/pdf 作答：先提取成文本再统计；图片作答按 `workspace-layout.md` 第 6 节
    先请用户转文本（经同意代转的，统计的是转写稿，并可并记占格行数粗估）。
- 报告里沿用精确值；若脚本结果与既有数字不一致，**以脚本为准**并说明；
  报告须同时登记**作答来源**（对话 / `作答记录/{省份}/{卷ID}.txt`），保证可追溯。
- 图片转写的作答：字数为转写稿统计值；能看出占格行数时可并记粗估（`行数 × 20`），
  两者相差 > 10% 时提示"转写可能漏字/多字"。

### 4.3 脚本命令速查

```bash
# 单块文本（示例答案、范文、转写稿）
python .dsh/skills/shenlun-judge/scripts/count_chars.py 答案.txt --limit 300 --label "第一题示例答案"
# "X 字左右"：带 ±10% 弹性
python .dsh/skills/shenlun-judge/scripts/count_chars.py 作文.txt --limit 1000 --approx
# "1000—1200 字"：给下限
python .dsh/skills/shenlun-judge/scripts/count_chars.py 作文.txt --limit 1200 --floor 1000
# 套卷整份作答（`作答记录/{省份}/` 目录）：按"第X大题/第X题"切块，--limits 按顺序给每题上限
python .dsh/skills/shenlun-judge/scripts/count_chars.py 作答记录/河南/2020河南乡镇.txt --split --limits 300,200,300,500,500
# 机器可读（便于落盘留痕）
python .dsh/skills/shenlun-judge/scripts/count_chars.py 答案.txt --limit 300 --json
python .dsh/skills/shenlun-judge/scripts/count_chars.py --selftest   # 自检
```

退出码：`0` = 统计完成（结论可能是"超出/偏少"，看结论行，**不是报错**）；`2` = 参数错误；
`3` = 文件不存在。

## 5. 示例答案的核验闭环（本文件的重点）

1. **先定要点，再定字数**：按采分点列出要写的点，估算总容量（每条最短字数 × 点数）；
   若已超过上限的 95%，**先砍点数**再写句子，不要写完再削。
2. **写成纯文本**：不用加粗、表格、引用块（markdown 标记会污染计数）。
3. **跑脚本**（带 `--limit`）。结论行含义：
   - `[达标]` → 可用；
   - `[贴限]`（> 95%）→ 有超限风险，继续压到 85%–95%；
   - `[超出]` → **禁止输出**，必须压缩后重新核验；
   - `[偏少]`（< 85%）→ 可补 1–2 个高价值要点，提高采分点命中数。
4. **压缩优先级**（从低价值到高价值，绝不删采分点关键词）：

   | 顺序 | 动作 | 例 |
   |---|---|---|
   | a | 删无采分点修饰 | "在……的过程中""切实""大力""不断" |
   | b | 合并同义重复 | "调研走访、入户了解"→"入户调研" |
   | c | 长并列收拢 | "气候、降水、日照、气温、土壤"→"自然条件适宜" |
   | d | 长句改并列短句、一条拆两条 | 便于阅卷扫读 |

5. **再跑脚本**，直到 `[达标]`；报告里写**最终**数字。
6. 确实装不下（要点数 × 每条最短字数 > 上限）：保留高价值要点，在答案末标注
   "（受字数限制，本答案覆盖 X 个参考采分点中的 Y 个）"，**依然不许超限**。
7. 一题多版本（直抄版 / 提炼版）→ **每个版本分别核验、分别报数**。
8. 用户要"参考范文"（整篇大作文）→ 同样核验：含标题字数落在 950–1050（"1000 字左右"）
   或题目区间内，超了先删一段冗余论证再核验。

## 6. 回退方案（脚本不可用时）

优先级：**Python 脚本 → Node → PowerShell → 人工估算（须标注未核验）**。

Node 一行（等价于脚本的答题卡口径）：

```bash
node -e "const s=require('fs').readFileSync(process.argv[1],'utf8');const t=s.replace(/^[ \t]*```.*$/gm,'').replace(/[|*`~_#>]/g,'').replace(/\s/g,'');console.log([...t].length)" 答案.txt
```

PowerShell 一行（Windows PowerShell 5.1 必须 `-Encoding UTF8`）：

```powershell
$t = (Get-Content -Raw -Encoding UTF8 答案.txt) -replace '[|*`~_#>]','' -replace '\s',''
$t.Length
```

- PowerShell 的 `.Length` 按 UTF-16 计：BMP 内汉字/标点各计 1，emoji 等代理对计 2；仅作兜底。
- 任何回退都必须输出"**脚本不可用，以下为估算**"的声明，且不得写成精确到个位的断言。
- **估算值一律不得作为示例答案的字数标注**：宁可去掉"（XX 字）"标注，也不写不实的数字。

## 7. 报告"字数核验"块（模板）

示例答案必须逐个报数——这是本次修正的直接落点：

```markdown
### 字数核验（`scripts/count_chars.py` 统计 · 答题卡口径，含标点）

| 对象 | 统计值 | 题目要求 | 占比 | 结论 |
|------|-------|---------|------|------|
| 示例答案·第一题 | 268 字 | 不超过 300 字 | 89.3% | 达标 |
| 示例答案·第二题 | 186 字 | 不超过 200 字 | 93.0% | 达标 |
| 参考范文·大作文 | 含标题 1004 字（正文 995 字） | 1000 字左右 | 弹性区间 900–1100 | 达标 |
| 用户作答·第一题 | 285 字 | 不超过 300 字 | 95.0% | 达标（贴限） |

> 核验命令：`python .dsh/skills/shenlun-judge/scripts/count_chars.py 批改报告/.字数核验/第一题示例答案.txt --limit 300`
> 口径说明：含标点、数字、字母、序号；不含空格换行与 markdown 标记。
```

- 示例答案的文本建议落盘到 `批改报告/.字数核验/`，并可复核（命令随报告留痕）。
- 大作文一律给"含标题 X 字（正文 Y 字）"分解。
- 采分点核对表里若出现"该要点约 X 字"，同样须逐条手数或脚本统计，不得估。

## 8. 自查清单（出报告前逐条过）

1. **每个示例答案都跑过脚本吗？都在 85%–95%（或区间题目标区）内吗？** 没跑就不许带数字输出。
2. 示例答案的标注字数，是不是脚本的**最终**值（压缩后重新数的），而不是压缩前的？
3. 我报的是"含标点数"还是"纯汉字数"？标注口径了吗？
4. 题干是"不超过/左右/区间/不少于"哪一种？上限取值对吗？大作文标题算不算？
5. 一题多版本时，是否每个版本分别核验？
6. 报告里有没有把报告自身标题、栏目名、批注算进字数？
7. 脚本不可用时，我是否明确标注了"估算、未核验"，且**没有**把估算值写成示例答案的字数标注？
