# 字数核验规范（唯一出处）

本文件是 shenlun-judge 处理"字数"问题的**唯一权威口径**：字数怎么数、怎么判定合规、
示例答案怎么保证不超限、用户作答怎么按口径计分、报告里怎么写。其他文件只做指引，不另立口径。

工具：`工具/count_chars.py`（Python 3 标准库，无第三方依赖；`--selftest` 可自检）。
**无 Python 的环境**用同参数的 Node／PowerShell 回退（见 §6）。

> ⚠ **本文件有两套口径，别混**：
> **① 示例答案/范文** → 硬约束：必须 ≤ 上限且落在 85%–95%，跑脚本核验后才输出（§4.1、§5）。
> **② 用户作答** → **核验并计分**：超限按用户口径扣分 `⌈超出达标上限 ÷ 50⌉`（§4.2）。
> 旧的"用户作答字数不扣分／只做合规核验"口径（2026-09、2026-09-19）**已废止**。

---

## 0. 要治的问题（根因）

**核心毛病：示例答案（含参考答案、满分答案、范文）字数超标，且标注的字数不实。**

已核实的事故：

> 2020 河南乡镇卷第一题（要求"不超过 300 字"），报告写"**参考作答要点（供对照，约 290 字）**"，
> 脚本实测 **384 字**（含标点）——**超上限 84 字，占比 128%**。标称值与实测值差 94 字。

成因有三个，都要在本文件里堵住：

1. **凭语感估数**：模型目测中文串长度误差可达 20% 以上，"约 290 字"是估出来的，不是数出来的；
2. **写答案时不带字数约束**：先把采分点写全、写完就交，没人回头核对上限；
3. **口径混乱**：汉字数、字符数、含标点数混用（历史报告里同时出现过"866 汉字""981 字符"
   两种写法），读者无法判断到底达没达标。

> 说明：用户作答字数此前"只核验不扣分"，2026-09-21 起改为**核验并计分**（§4.2）；
> 本文件不对历史报告中的旧写法作追溯性否定。

## 1. 三个口径必须分开

| | **评分口径**（扣不扣分） | **核验口径**（合不合规） | **示例答案口径**（硬约束） |
|---|---|---|---|
| 对象 | **用户作答** | **用户作答** | **助手给的示例答案 / 范文** |
| 依据 | **用户 2026-09-21 口径**：`扣分 = ⌈超出达标上限 ÷ 50⌉` | 题干字数要求是 **L1**，必须核验（逐字符统计，精确到 1 字） | 必须 **≤ 题目上限**且落在 **85%–95%** |
| 结论 | **超限扣分**（字数过少不扣）；扣分只计"字数"这一项，**不作降档理由** | 给**定性结论**（符合／超出上限／明显偏少） | 给"X 字 / 上限 N 字 / 占比 %"，**未核验不得标注字数** |
| 出处 | §4.2（唯一计分公式） | 本文件 | 本文件 §4.1／§5 |

- **"必须核验"**：L1 要求真实存在，所以**不能不查**。
- **扣分公式只有一个**（用户口径）：`扣分 = ⌈超出达标上限的字数 ÷ 50⌉`。
  **禁止**自创别的换算（"每超 10 字扣 0.5 分""按百分比扣分"）；
  **禁止**把它写成"官方罚则"——官方从未公布罚则，这是**用户裁定口径**。
- **禁止的错误推理**："反正字数只扣一点点，所以示例答案写多长都行"——示例答案是给用户**模仿**的，
  它超限等于教用户在考场上超限，比报错数字更严重。

## 2. 计数口径（答题卡口径 = 主口径）

**计入（每字符占答题卡一格）**：

- 汉字；
- 标点（，。、；：""''！？——……《》等，全角半角各计 1）；
- 数字与字母（2024、GDP、5G 的每个字符各计 1）；
- 序号（"1."、"（2）"、"一、"、"一是"）；
- 标题、称呼、落款、日期。

**不计入**：

- 空格、制表符、换行（在格子之外）；
- **助手转写/排版时添加的 markdown 标记**：`**` `` ` `` `#` `>` `|` `~`、列表符 `- `/`* `、
  代码围栏 ```` ``` ````——这些不是考生写的，脚本会自动净化；
- **以 `【说明】`「【批注】」「【备注】」「【转写说明】」「【作答说明】」开头的说明段**
  （从该行到空行或文末）：这是背景说明，不是答题内容，**不占答题卡格子**；
  脚本剔除后会输出"[提示] 已剔除 N 段【说明】类说明文字"。
  行内的 `【作答】`「【答案】」「（转写存疑）」「（此处略）」「（约 X 字）」等标注同样不计入；
- 报告自身的栏目名与标题行（如"【作答】""【满分答案】""（此处为报告批注）"）。

**报告用语统一为"X 字（含标点）"**，不得只写"X 字"造成口径歧义；需要解释构成时附辅助口径
（纯汉字数、去行首序号数）。

## 3. 先识别题干的字数要求（识别错，后面全错）

| 题干表述 | 类型 | 判定与扣分 | **示例答案目标区** |
|---|---|---|---|
| 不超过 300 字 / 300 字以内 / 限 300 字 | 硬上限 | 达标上限 = **300**；实际 > 300 → **扣分 = ⌈(实际−300) ÷ 50⌉** | **255–285（85%–95%）** |
| 300 字左右 / 约 300 字 | **弹性 ±50**（用户口径 2026-09-21） | 达标区 **250–350**；实际 > 350 → **扣分 = ⌈(实际−350) ÷ 50⌉** | 270–320 |
| 1000—1200 字 | 区间 | < 1000 或 > 1200 均不合要求（**区间题未给扣分公式，见下方说明**） | 1050–1150 |
| 不少于 800 字 / 800 字以上 | 下限 | < 800 偏少（**字数过少不扣分**，按内容/结构如实反映） | 850–1000 |
| 总字数 1000 字左右（大作文） | **弹性 ±50**（用户口径 2026-09-21） | 达标区 **950–1050**；实际 > 1050 → **扣分 = ⌈(实际−1050) ÷ 50⌉** | 950–1050 |

> **依据层级**：题干给出的字数限制是**官方公开的作答要求（L1）**，**必须核验**；
> 而扣分公式是**用户 2026-09-21 裁定的评分口径（非官方罚则）**——
> 报告中写"**按用户字数口径扣分**"，**不得**写成"官方规定超字数扣分"。
> 表中"示例答案目标区（85%–95%）"是**本 skill 的训练建议（L3）**，同样不得写成官方要求。

- 题干未给字数要求 → 只报统计值，不判定合规性，也**不适用扣分公式**，并提示"题干未给字数要求"。
- **大作文的标题是否计入**：题干说"总字数"含标题；题干另说"正文"则不含标题。
  报告一律给分解：`含标题 X 字（其中正文 Y 字）`。
- **区间题（1000—1200 字）**：用户口径只规定了"不超过 XX""XX 字左右"两种；
  区间题先按区间判定合规，**是否按上限扣分须先向用户确认**，不得自行套用、也不得自创比例。
- **扣分按"字"算**：50 字一块、向上取整（不足 50 也算一块），不按百分比、不按行数。

## 4. 标准动作

### 4.1 示例答案 / 满分答案 / 范文（必做，硬约束）

**示例答案必须 ≤ 题目上限且落在上限的 85%–95%**（区间题按 §3 目标区）。
流程：**写要点 → 写成纯文本 → 跑脚本 → 不达标就压缩 → 再跑脚本 → 达标才输出**（详见 §5）。

### 4.2 用户作答：**按用户字数口径核验并计分**（用户口径 2026-09-21；覆盖 2026-09／2026-09-19 旧口径）

> **★ 唯一计分公式（用户 2026-09-21 原话口径）**
>
> ```
> 扣分 = ⌈超出达标上限的字数 ÷ 50⌉        # 向上取整：不足 50 也算一块
> ```
>
> | 题干表述 | 达标上限 | 扣分起点 |
> |---|---|---|
> | **不超过 XX 字** | **XX 字** | 实际 > XX → 扣分 = ⌈(实际 − XX) ÷ 50⌉ |
> | **XX 字左右** | **XX + 50 字** | 实际 > XX+50 → 扣分 = ⌈(实际 − (XX+50)) ÷ 50⌉ |
>
> **示例（用户给的算例）**：限 300 字、实写 374 字 → 超 74 字 → ⌈74÷50⌉ = **扣 2 分**。
> "300 字左右"的达标区是 **250–350**；写 351–400 扣 1 分，401–450 扣 2 分，依此类推。
>
> - **字数过少不扣分**（用户 2026-09-21："不考虑字数过少的情况"）。
>   作答明显被截断时，仍按**结构完成度**如实反映，但不另立"字数不足"扣分项。
> - 本条**优先于**本 skill 及各处文件中"用户作答字数不扣分／只做合规核验"的表述——
>   那些是 2026-09 与 2026-09-19 的旧口径，**已废止**。

- **核验方式**：用户作答是纯文本，**可以直接统计**——
  `python 工具/count_chars.py 作答记录/{省份}/{卷ID}.txt --split --limits 300,250,400,450,1200`。
  报告里**不写"用户作答 X 字"这类总字数**，只写**达标判定 ＋ 超出量与扣分**。
- **超出上限**：报告单列一行
  **"⚠ 字数扣分：超出达标上限 X 字 → 扣 Y 分（按用户字数口径）"**（X、Y 由上方公式算出），
  并在**改进方向**里给出压缩到限内的具体建议（删哪几句、哪一段可合并）。
- **明显少于要求**（如要求"不少于 800 字"却只写 300 字）：按**结构完成度／内容质量**如实反映，
  **不单列"字数不足"扣分项**；作答**明显被截断**（尾部断句、无收束、主体残缺）同此处理。
- **扣分只计"字数"这一项**：**不得**再据此降档，也不得二次计入内容／结构维度。
- **不核验的情形**：作答来自图片且用户未转写、题面未给字数要求、或用户明确说"别数字数"——
  此时只登记"未核验"与原因，**不得**反过来写成"默认满足要求"。
- **作答来源**：优先用对话里贴出的作答；否则到工作区 **`作答记录/{省份}/`** 取对应文件
  （匹配与命名约定见 `SKILL.md` 第三节第 1 步；**`作答记录/` 只收 md/txt**，
  图片请用户先自行转文本）。
- **用户主动问"我写够了没有"**：给行数粗估——答题卡每行约 20 字，"要求字数 ÷ 20 ＝ 应占行数"；
  纯正文实际占用行数 ≥ 该值即达到要求（标题单独占行）。这是**粗估工具**，不是评分依据。
- 报告须登记**作答来源**（对话 / `作答记录/{省份}/{卷ID}.txt`），保证可追溯。

### 4.3 脚本命令速查

```bash
# 单块文本（示例答案、范文、转写稿）
python 工具/count_chars.py 答案.txt --limit 300 --label "第一题示例答案"
# "X 字左右"：带 ±50 弹性（用户口径 2026-09-21）
python 工具/count_chars.py 作文.txt --limit 1000 --approx
# "1000—1200 字"：给下限
python 工具/count_chars.py 作文.txt --limit 1200 --floor 1000
# 套卷整份作答（`作答记录/{省份}/` 目录）：按"第X大题/第X题"切块，--limits 按顺序给每题上限
python 工具/count_chars.py 作答记录/河南/2020河南乡镇.txt --split --limits 300,200,300,500,500
# 机器可读（便于落盘留痕）
python 工具/count_chars.py 答案.txt --limit 300 --json
python 工具/count_chars.py --selftest   # 自检
```

退出码：`0` = 统计完成（结论可能是"超出/偏少"，看结论行，**不是报错**）；`2` = 参数错误；
`3` = 文件不存在。

## 5. 示例答案的核验闭环（本文件的重点）

1. **先定要点，再定字数**：按采分点列出要写的点，估算总容量（每条最短字数 × 点数）；
   若已超过上限的 95%，**先砍点数**再写句子，不要写完再削。
2. **写成纯文本**：不用加粗、表格、引用块（markdown 标记会污染计数）。
3. **跑脚本**（带 `--limit`）。结论行含义：
   - `[达标]` → 可用；
   - `[贴限]`（> 95%）→ 有超限风险，继续压到 85%–95%；
   - `[超出]` → **禁止输出**，必须压缩后重新核验；
   - `[偏少]`（< 85%）→ 可补 1–2 个高价值要点，提高采分点命中数。
4. **压缩优先级**（从低价值到高价值，绝不删采分点关键词）：

   | 顺序 | 动作 | 例 |
   |---|---|---|
   | a | 删无采分点修饰 | "在……的过程中""切实""大力""不断" |
   | b | 合并同义重复 | "调研走访、入户了解"→"入户调研" |
   | c | 长并列收拢 | "气候、降水、日照、气温、土壤"→"自然条件适宜" |
   | d | 长句改并列短句、一条拆两条 | 便于阅卷扫读 |

5. **再跑脚本**，直到 `[达标]`；报告里写**最终**数字。
6. 确实装不下（要点数 × 每条最短字数 > 上限）：保留高价值要点，在答案末标注
   "（受字数限制，本答案覆盖 X 个参考采分点中的 Y 个）"，**依然不许超限**。
7. 一题多版本（直抄版 / 提炼版）→ **每个版本分别核验、分别报数**。
8. 用户要"参考范文"（整篇大作文）→ 同样核验：含标题字数落在 950–1050（"1000 字左右"）
   或题目区间内，超了先删一段冗余论证再核验。

## 6. 回退方案（脚本不可用时）

优先级：**Python 脚本 → Node 一行 → PowerShell 一行 → 人工估算（须标注未核验）**。

Node 一行（等价于脚本的答题卡口径）：

```bash
node -e "const s=require('fs').readFileSync(process.argv[1],'utf8');const t=s.replace(/^[ \t]*```.*$/gm,'').replace(/[|*`~_#>]/g,'').replace(/\s/g,'');console.log([...t].length)" 答案.txt
```

PowerShell 一行（Windows PowerShell 5.1 必须 `-Encoding UTF8`）：

```powershell
$t = (Get-Content -Raw -Encoding UTF8 答案.txt) -replace '[|*`~_#>]','' -replace '\s',''
$t.Length
```

- PowerShell 的 `.Length` 按 UTF-16 计：BMP 内汉字/标点各计 1，emoji 等代理对计 2；仅作兜底。
- 任何回退都必须输出"**脚本不可用，以下为估算**"的声明，且不得写成精确到个位的断言。
- **估算值一律不得作为示例答案的字数标注**：宁可去掉"（XX 字）"标注，也不写不实的数字。
- **用户作答的扣分不因脚本不可用而放弃**：用回退方式统计出字数后仍按 §4.2 公式计分，
  但须在报告注明"字数为回退统计（非脚本）、扣分按用户口径"。

## 8. 自查清单（出报告前逐条过）

1. **每个示例答案都跑过脚本吗？都在 85%–95%（或区间题目标区）内吗？** 没跑就不许带数字输出。
2. 示例答案的标注字数，是不是脚本的**最终**值（压缩后重新数的），而不是压缩前的？
3. 我报的是"含标点数"还是"纯汉字数"？标注口径了吗？
4. 题干是"不超过/左右/区间/不少于"哪一种？**达标上限取值对吗**（"左右"要 +50）？大作文标题算不算？
5. **用户作答的字数，我按 §4.2 核验并计分了吗**——超限有没有单列"⚠ 字数扣分"？
   有没有**错把它当成降档理由**、或**自创了别的扣分公式**？
6. 一题多版本时，是否每个版本分别核验？
7. 报告里有没有把报告自身标题、栏目名、批注算进字数？
8. 脚本不可用时，我是否明确标注了"估算、未核验"，且**没有**把估算值写成示例答案的字数标注？
