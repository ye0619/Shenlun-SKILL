# 字数核验规范（唯一出处）

本文件是 shenlun-judge 处理"字数"问题的**唯一权威口径**：字数怎么数、怎么判定合规、
示例答案怎么保证不超限、**用户作答的字数怎么处理（只核验、不计分）**、报告里怎么写。
其他文件只做指引，不另立口径。

工具：`工具/count_chars.py`（Python 3 标准库，无第三方依赖；`--selftest` 可自检）。
**正式脚本不可用时**可用 Node／PowerShell 辅助粗估（见 §6），不能替代正式字数核验。

> ⚠ **按文本来源区分字数处理**：
> **① 助手自行撰写的答案** → 小题／公文正文须满足题干字数要求并经脚本核验，85%–95% 仅作建议，必要要点完整性优先（`rulings.md` §1.9）；AI 模拟范文须按题干类型满足对应生成目标区（§3、§4.1、§5）。
> **② 用户作答** → **只做合规核验，不计入评分**（用户口径 **2026-09-27**，§4.2）：
> 超限只在报告里单列一句**提示**，**不扣分、不降档、不进任何分值**。
> **③ 本卷参考答案收录的完整范文** → 按 `rulings.md` §1.8 核验并提示；超限、偏少或偏离目标区均不影响候选、排序、预评分或模拟档位，必须整篇照录，不压缩补写（§4.4）。
> ⛔ **已废止**：`扣分 = ⌈超出达标上限 ÷ 50⌉`（2026-09-21 立、2026-09-25 重申）；
> ⛔ 也已废止 2026-09／2026-09-19 那套"只核验不扣分"的**表述**（那套说"报告单列 L1 合规问题"，
> 与本条实质相同，但**表述口径以本文件 §4.2 为准**）。

## 0. 要治的问题（根因）

**核心毛病：助手自行撰写的示例答案／AI 模拟范文未遵守生成字数要求，或标注字数不实。收录完整范文按 §4.4 处理，字数偏差本身不是错误。**

已核实的事故：

> 2020 河南乡镇卷第一题（要求"不超过 300 字"），报告写"**参考作答要点（供对照，约 290 字）**"，
> 脚本实测 **384 字**（含标点）——**超上限 84 字，占比 128%**。标称值与实测值差 94 字。

成因有三个，都要在本文件里堵住：

1. **凭语感估数**：模型目测中文串长度误差可达 20% 以上，"约 290 字"是估出来的，不是数出来的；
2. **写答案时不带字数约束**：先把采分点写全、写完就交，没人回头核对上限；
3. **口径混乱**：汉字数、字符数、含标点数混用（历史报告里同时出现过"866 汉字""981 字符"
   两种写法），读者无法判断到底达没达标。

> **注意本文件真正要治的是"示例答案"**。用户作答的字数**从来不是失分点**——
> 2026-09-21 曾一度把它改成"超限扣分"，2026-09-27 用户裁定**改回不计分**（§4.2）。
> 本文件不对历史报告中的旧写法作追溯性否定。

## 1. 三个口径必须分开

| | **评分口径**（扣不扣分） | **核验口径**（合不合规） | **示例答案口径**（生成要求） |
|---|---|---|---|
| 对象 | **用户作答** | **用户作答** | **助手自行撰写的示例答案／AI 模拟范文** |
| 依据 | **用户 2026-09-27 口径：字数不计入评分**（超限不扣分、不降档） | 题干字数要求是 **L1**，必须核验（逐字符统计，精确到 1 字） | 小题／公文须符合题干字数要求，目标区仅作建议（`rulings.md` §1.9）；AI 模拟范文须按 §3／§4.1 的题干类型满足对应生成目标区 |
| 结论 | **不扣分**；只在报告单列一句**提示**（超出／偏少／达标） | 给**定性结论**（符合／超出上限／明显偏少） | 给"X 字 / 上限 N 字 / 占比 %"，**未核验不得标注字数** |
| 出处 | §4.2 | 本文件 | 本文件 §4.1／§5 |

- **"必须核验"**：L1 要求真实存在，所以**不能不查**——查完是**提示**，不是扣分。
- 本表生成要求不用于收录完整范文；此类原文按 §4.4 核验，字数偏差不影响选取、排序或评分。
- **禁止自创扣分公式**：不得"每超 10 字扣 0.5 分""按百分比扣分"，也**不得把它写成官方罚则**
  ——官方从未公布字数罚则。用户已明确**字数不计入评分**。
- **禁止的错误推理**："反正字数不计分，所以示例答案写多长都行"——示例答案是给用户**模仿**的，
  它超限等于教用户在考场上超限，比报错数字更严重。**用户不因字数失分 ≠ 助手可以写超**。

## 2. 计数口径（答题卡口径 = 主口径）

**计入（每字符占答题卡一格）**：

- 汉字；
- 标点（，。、；：""''！？——……《》等，全角半角各计 1）；
- 数字与字母（2024、GDP、5G 的每个字符各计 1）；
- 序号（"1."、"（2）"、"一、"、"一是"）；
- 标题、称呼、落款、日期。

**不计入**：

- 空格、制表符、换行（在格子之外）；
- **助手转写/排版时添加的 markdown 标记**：`**` `` ` `` `#` `>` `|` `~`、列表符 `- `/`* `、
  代码围栏 ```` ``` ````——这些不是考生写的，脚本会自动净化；
- **装饰线 / 分隔线**：单独占一行的 ≥3 个同字符（`=====`、`-----`、`*****`、`~~~~~`、`#####` 等）。
  这些是整理作答文件时加的分隔排版，**不占答题卡格子**；
  脚本已自动剔除（2026-10-11 修复，见 §9 事故行）。
  但**文件开头/结尾的标题块、页眉块（如"XX 省考·第 N 题作答"）不会被自动剔除**，
  须人工判断：非答题正文的 → 单列为"卷首/卷尾"并**不计入任何一题**；
- **以 `【说明】`「【批注】」「【备注】」「【转写说明】」「【作答说明】」开头的说明段**
  （从该行到空行或文末）：这是背景说明，不是答题内容，**不占答题卡格子**；
  脚本剔除后会输出"[提示] 已剔除 N 段【说明】类说明文字"。
  行内的 `【作答】`「【答案】」「（转写存疑）」「（此处略）」「（约 X 字）」等标注同样不计入；
- 报告自身的栏目名与标题行（如"【作答】""【满分答案】""（此处为报告批注）"）。

**报告用语统一为"X 字（含标点）"**，不得只写"X 字"造成口径歧义；需要解释构成时附辅助口径
（纯汉字数、去行首序号数）。

## 3. 先识别题干的字数要求（识别错，后面全错）

| 题干表述 | 类型 | 达标判定 | **示例答案目标区** |
|---|---|---|---|
| 不超过 300 字 / 300 字以内 / 限 300 字 | 硬上限 | 达标上限 = **300**；实际 > 300 → **不合要求**（提示） | **255–285（85%–95%）** |
| 300 字左右 / 约 300 字 | **弹性 ±50**（用户口径 2026-09-21） | 达标区 **250–350**；实际 > 350 → **不合要求**（提示） | 270–320 |
| 1000—1200 字 | 区间 | < 1000 或 > 1200 均不合要求 | 1050–1150 |
| 不少于 800 字 / 800 字以上 | 下限 | < 800 偏少 → **如实提示**（**不扣分**） | 850–1000 |
| 总字数 1000 字左右（大作文） | **弹性 ±50**（用户口径 2026-09-21） | 达标区 **950–1050**；实际 > 1050 → **不合要求**（提示） | 950–1050 |

> **依据层级**：题干给出的字数限制是**官方公开的作答要求（L1）**，**必须核验**；
> 而"超出怎么算"在本 skill 里**不产生任何分值**（用户 2026-09-27 裁定）——
> 报告中只写"**超出题干上限 X 字（按用户口径不计分）**"，
> **不得**写成"官方规定超字数扣分"，**也不得**自己给它配一个扣分公式。
> 表中“示例答案目标区”是**本 skill 的训练目标（L3）**，不得写成官方要求。
> 小题／公文的目标区仅作建议，具体取舍按 `rulings.md` §1.9；AI 模拟范文按所识别的题干类型使用对应目标区，仅硬上限题采用 85%–95%，其他类型不叠加该比例，详见 §4.1。

- 题干未给字数要求 → 只报统计值，不判定合规性，并提示"题干未给字数要求"。
- **大作文的标题是否计入**：题干说"总字数"含标题；题干另说"正文"则不含标题。
  报告一律给分解：`含标题 X 字（其中正文 Y 字）`。
- **区间题（1000—1200 字）**：先按区间判定合规；不合规时只提示，**不折算分值**。

## 4. 标准动作

### 4.1 助手自行撰写的答案：按题型区分生成要求

- **小题／公文参考正文**：须满足题干字数要求并经脚本核验；85%–95% 仅作建议目标，必要要点完整性与容量冲突处理统一按 `rulings.md` §1.9，不为凑比例删点或填充。
- **AI 模拟范文**：先识别 §3 的题干类型，同时满足题干要求与对应生成目标。硬上限题使用上限的 85%–95%；“左右”、区间与下限题使用 §3 表中的对应目标区，不再叠加 85%–95%。例如“1000 字左右”生成目标为 950–1050 字，“1000—1200 字”为 1050–1150 字，“不少于 800 字”为 850–1000 字；“左右”的中心值不能当作硬上限，下限题目标区的上沿也不是题干上限。题干未给字数要求时只统计，不虚设上限或目标区。

流程：**写要点 → 写成纯文本 → 跑脚本 → 按题干字数要求及适用生成目标调整 → 修改后再核验 → 符合对应要求后输出**（详见 §5）；小题／公文不能只因偏离建议目标区而反复压缩或补写。

### 4.2 用户作答：**只做合规核验，不计入评分**（用户口径 **2026-09-27**）

> **★ 唯一结论（用户 2026-09-27 裁定）**
>
> ```
> 字数不计入评分：超限不扣分、不降档、不进任何分值；只在报告里单列一句提示。
> ```
>
> | 题干表述 | 达标判定 | 不符时怎么处理 |
> |---|---|---|
> | **不超过 XX 字** | 实际 ≤ XX 为达标 | 超出 → 报告写"超出题干上限 X 字（**按用户口径不计分**）" |
> | **XX 字左右** | 达标区 **XX±50** | 超出达标区 → 同上（**不按 50 字一块折算**） |
> | **区间题 / 不少于 N 字** | 按区间或下限判 | 不符 → 同上 |
>
> - ⛔ **已废止**（勿再执行）：`扣分 = ⌈超出达标上限的字数 ÷ 50⌉`。
>   该公式 2026-09-21 由用户立、2026-09-25 重申，**2026-09-27 用户裁定整体废止**——
>   理由是**字数不进入评分**。
> - **禁止**再据此降档，**禁止**二次计入内容／结构维度，**禁止**自创别的换算。
> - **字数偏少只作提示**，不作为内容或结构评分的触发条件，不因篇幅较短推断内容残缺、论证不足或结构不完整。
> - 作答原文确有**截断、主体残缺、未完成收束等实质问题**时，须引用具体原文，按适用题型的既有内容／结构规则判断；不能以字数少替代证据，不单列"字数不足"扣分项，也不对同处问题重复扣分。
> - **过渡期报告（2026-09-21 — 2026-09-27 之间出的）**：报告里可能出现"⚠ 字数扣分"与
>   被拉低的总分（如某卷因超 4 字／5 字各扣 1 分）。**那批报告留作历史记录，不回改**；
>   引用或对比时须注明"该分数含已废止的字数扣分"，**不要与新口径报告直接比总分**。

- **核验方式**：用户作答是纯文本，**可以直接统计**——
  `python 工具/count_chars.py 作答记录/{省份}/{卷ID}.txt --split --limits 300,250,400,450,1200`。
  报告里**不写"用户作答 X 字"这类总字数**，只写**达标判定 ＋ 超出量（不计分）**。
- **超出上限**：报告单列一行
  **"⚠ 字数提示：超出题干上限 X 字（按用户口径不计分）"**，
  并在**改进方向**里给出压缩到限内的具体建议（删哪几句、哪一段可合并）——
  **建议照给，分不扣**：考场上的字数风险是真实的，只是不由本 skill 计分。
- **不核验的情形**：作答来自图片且用户未转写、题面未给字数要求、或用户明确说"别数字数"——
  此时只登记"未核验"与原因，**不得**反过来写成"默认满足要求"。
- **作答来源**：优先用对话里贴出的作答；否则到工作区 **`作答记录/{省份}/`** 取对应文件
  （匹配与命名约定见 `SKILL.md` 第三节第 1 步；**`作答记录/` 只收 md/txt**，
  图片请用户先自行转文本）。
- 报告须登记**作答来源**（对话 / `作答记录/{省份}/{卷ID}.txt`），保证可追溯。

### 4.3 脚本命令速查

```bash
# 单块文本（示例答案、范文、转写稿）
python 工具/count_chars.py 答案.txt --limit 300 --label "第一题示例答案"
# "X 字左右"：带 ±50 弹性（用户口径 2026-09-21）
python 工具/count_chars.py 作文.txt --limit 1000 --approx
# "1000—1200 字"：给下限
python 工具/count_chars.py 作文.txt --limit 1200 --floor 1000
# 只有下限、没有上限：只统计实际字数，再对照题干下限与适用生成目标
python 工具/count_chars.py 作文.txt --json
# 套卷整份作答（`作答记录/{省份}/` 目录）：按"第X大题/第X题"切块，--limits 按顺序给每题上限
python 工具/count_chars.py 作答记录/河南/2020河南乡镇.txt --split --limits 300,200,300,500,500
# 机器可读（便于落盘留痕）
python 工具/count_chars.py 答案.txt --limit 300 --json
python 工具/count_chars.py --selftest   # 自检
```

退出码：`0` = 统计完成（结论可能是"超出/偏少"，看结论行，**不是报错**）；`2` = 参数错误；
`3` = 文件不存在。
仅下限题不虚填 `--limit`；脚本只输出统计值时，助手须据实际字数分别核对题干下限与 §3 的适用生成目标，不能把“仅统计”说成工具已自动判定合规。

### 4.4 收录完整范文：只核验与提示，不影响选取或评分

执行 `rulings.md` §1.8。统计实际字数，按题干要求如实提示超限／偏少；不把 `[超出]`、`[偏少]` 或未落目标区当作拒绝展示、降档或择优劣势。核验后仍整篇原样照录，不执行 §5 的压缩、补写或删段流程。完整性须看原文是否真实截断、缺段等证据，不能由字数少推断。字数未完成核验时如实标明状态，不编造精确值。

## 5. 示例答案的核验闭环（本文件的重点）

本节只适用于**助手自行撰写**的示例答案或 AI 模拟范文；参考答案收录的完整范文按 §4.4 处理，不套用本节的压缩与达标才输出要求。

1. **先定要点，再定字数**：按采分点列出要写的点，估算总容量（每条最短字数 × 点数）；
   小题／公文优先压缩重复解释、冗余修饰和句式长度，**不得为命中建议目标区而删除必需采分点**；完整覆盖后符合题干要求即可，不为凑比例删点或填充。若实际改写核验后仍超过硬上限，按 `rulings.md` §1.9 处理。
   AI 模拟范文先按 §3／§4.1 确定本题适用生成目标，偏离时调整有效内容或冗余，不把非硬上限题机械压到 85%–95%。
2. **写成纯文本**：不用加粗、表格、引用块（markdown 标记会污染计数）。
3. **跑脚本**（按题干选择 `--limit`、`--floor` 或 `--approx`）。结论行须结合题型及实际字数要求解释，不能直接当作全部交付条件：
   - `[达标]` → 统计范围符合工具所用条件；仍须核对必要要点覆盖。AI 模拟范文另核对 §3／§4.1 的适用生成目标，例如区间题在题干范围内不等于已经落入生成目标区。
   - `[贴限]`（仅硬上限模式中出现，> 95%）→ 小题／公文在符合题干字数要求且必要要点完整时可输出，不强制压回建议目标区；AI 模拟范文的硬上限题仍须压到 85%–95%。不能误用硬上限模式检查“左右”、区间或仅下限题。
   - `[超出]` → **禁止输出**，必须压缩后重新核验；
   - `[偏少]` → 先区分低于建议目标区还是低于题干明确下限；小题／公文仅低于建议目标区、必要要点已完整且符合题干要求时可输出，不为凑比例填充。低于题干下限仍须补足相关内容并重新核验；AI 模拟范文须满足 §3／§4.1 按题干类型选定的生成目标。
4. **压缩优先级**（从低价值到高价值，绝不删采分点关键词）：

   | 顺序 | 动作 | 例 |
   |---|---|---|
   | a | 删无采分点修饰 | "在……的过程中""切实""大力""不断" |
   | b | 合并同义重复 | "调研走访、入户了解"→"入户调研" |
   | c | 长并列收拢 | "气候、降水、日照、气温、土壤"→"自然条件适宜" |
   | d | 长句改并列短句、一条拆两条 | 便于阅卷扫读 |

5. **再跑脚本**，报告里写最终正文的实际数字；小题／公文不为建议目标区删必要信息，实际超过题干硬上限时按下一步处理。AI 模拟范文按 §3／§4.1 的题干类型与对应生成目标核验。
6. 小题／公文经去重、保要点压缩及实际核验后，确实无法同时满足硬上限和完整覆盖：按 `rulings.md` §1.9 同题给**限字正文＋完整要点清单**。正文不得超限，正文外列明未覆盖项与取舍原因；完整清单供复盘，不冒充限字答卷，也不补算正文遗漏的分值，不称覆盖不足正文为满分答案。正文和清单分开，字数核验只统计正文。
7. 一题多版本（直抄版 / 提炼版）→ **每个版本分别核验、分别报数**。
8. 用户明确要求**助手撰写 AI 模拟范文**（整篇大作文）→ 按 §3／§4.1 选定对应生成目标并核验；引用已收录完整范文时改按 §4.4，只提示字数偏差，不删改原文。

## 6. 回退方案（脚本不可用时）

优先使用已有的 Python 正式脚本；无法运行时，Node／PowerShell 或人工估算仅作辅助粗估，统一标注“未完成脚本字数核验”，不作为合规判定或交付核验结果。

Node 一行（仅作粗估，未完整复现正式脚本的说明段、标签与分隔线净化规则）：

```bash
node -e "const s=require('fs').readFileSync(process.argv[1],'utf8');const t=s.replace(/^[ \t]*```.*$/gm,'').replace(/[|*`~_#>]/g,'').replace(/\s/g,'');console.log([...t].length)" 答案.txt
```

PowerShell 一行（仅作粗估；Windows PowerShell 5.1 必须 `-Encoding UTF8`）：

```powershell
$t = (Get-Content -Raw -Encoding UTF8 答案.txt) -replace '[|*`~_#>]','' -replace '\s',''
$t.Length
```

- PowerShell 的 `.Length` 按 UTF-16 计：BMP 内汉字/标点各计 1，emoji 等代理对计 2；且上述回退未完整复现正式净化规则，结果只能视为粗估。
- 任何回退都必须声明“**脚本不可用，以下仅为粗估；未完成脚本字数核验**”。即使输出为整数，也不得据此标注精确字数或精确超出量。
- **估算值一律不得作为示例答案或 AI 模拟范文的字数标注**，不得据此声称已完成核验或把示例作为已核验产物交付；正式核验要求仍按 §4.1／§5 与运行环境约定执行。
- **用户作答同理**：仅提示“未完成脚本字数核验，待核验”，不得根据回退粗估判定“达标／超出／偏少”；**不产生任何扣分**（§4.2）。
