## 作者自述：这个 skill 是怎么来的

**前排提醒**：由于申论批改是一个巨大的黑箱，没有官方的答案和评分标准，所以只能依靠市面上的参考答案和评分标准模拟评分。所以很可能是在错误的答案上建立的错误标准，批改仅供参考。

我想尽可能去打造一套模板而不是一个确定的评分标准，项目内包含“真题”、“参考答案”、“批改规范”等，你可自行上传，也可以使用你认为可靠的批改规范，你还可以为每套真题自定义批改规范（文件不存在则使用默认），由此达到你认为可靠的批改效果。

**9.19 修改**：受阅卷流程启发——真实阅卷是先抽一批卷试批改，才定下评分标准。所以现在只要你上传了某套题的
参考答案，它批改前会先拿参考答案自己试批一遍、建立一个采分点共识，由此得出参考答案，然后再进行评分。对于大作文，它会先对参考范文进行定档，再拿你的作文和范文对比，不过在ds的评测下范文也只能是二类（笑）。


**9.22 修改**：修改给分过高的bug（笑）。从网上搜集了几份国考评分规范，据此重写了 skill。
感新月的建议，加进了 **MinerU**（把 pdf、docx、png、jpg 转成 md 的工具，本地也能部署：
https://github.com/opendatalab/MinerU ）。现在口径严格了，但还是很难完全模拟真人阅卷——
毕竟 AI 会把你每个字都过一遍，不漏过任何一个得分点。
同时将09年到26年的国考真题md文件上传。

**9.25 修改**：感谢1591kks的建议，根据他的评分标准进行了完善。

**一些碎碎念**：其实提高批改的准确率有个简单而直接的方法，就是搜集一批考场上的答案以及得分，如果数据足够大，便可以将部分作为训练集、部分作为测试集。但整个工程会耗费大量时间、精力和金钱，个人很难做好，可能机构有能力做吧。
如果你有多考几次的打算，便可以根据自己考场上的作答以及分数，对skill进行调试，但如果真这么做了说明当年没考上（哭笑）。

还有就是经过几次修改，单次批改token消耗成功翻倍了（苦笑）。

## 项目结构

```text
shenlun/
├── .dsh/skills/shenlun-judge/     # skill 本体：SKILL.md + references/*.md（评卷口径全在这里）
├── 真题/                           # 试卷原题：{省份}/{卷ID}.pdf + 整理好的 {省份}/{卷ID}.md
├── 参考答案/                       # 机构/真题参考答案：{省份}/{卷ID}/第N题.txt
├── 作答记录/                       # 你的作答（只收 md / txt）：{省份}/{卷ID}.txt
├── 批改报告/                       # 报告落盘：{省份}/{卷ID}-批改报告.md（+ 字数核验/共识表/刻度缓存）
├── 批改规范/                       # 某卷（尤其大作文）的批改规范：{省份}/{卷ID}-批改规范.md
├── 工具/                           # 配套脚本：count_chars.py（字数）、ref_independence.py（同源检测）
├── bin/install.js                  # npx 一键安装器
├── templates/workspace/            # 安装时写进新工作区的目录说明模板
├── fenbi-pdf-downloader.user.js    # 配套油猴脚本：粉笔试卷批量下载
└── package.json / README.md / LICENSE / .gitignore
```

**用途**

| 目录 | 放什么 | 谁放 |
|---|---|---|
| `作答记录/` | **你的作答**（批改对象），整卷一份或按题拆，**只收 md / txt** | 你 |
| `参考答案/` | 机构参考答案 / 真题参考答案，一题一文件 | 你收集，助手登记 |
| `批改规范/` | 某套卷的批改规范；批改该卷时**有就必须引用** | 你收集（或用助手试批改的草稿） |
| `批改报告/` | 报告母本；另存字数核验留痕、采分点共识表、大作文刻度缓存 | 助手自动落盘 |
| `真题/` | 原卷 PDF ＋ 整理好的 md（题面与材料是**最高依据**） | 你收集／助手整理 |
| `工具/` | `count_chars.py`、`ref_independence.py` | 随仓库发布，**路径固定，别改名** |
| `.dsh/skills/shenlun-judge/` | skill 本体：`SKILL.md` ＋ `references/` | 本仓库维护 |

> 仓库里**不放个人材料**：`作答记录/`、`批改报告/`、`参考答案/`、`批改规范/` 只上传空框架
> （README ＋ `.gitkeep`），`真题/` 只上传 `国考/*.md`。PDF、个人作答、机构资料都不入库。

## 快速开始

### 一键安装（npx）

本仓库自带一个零依赖安装器，一条命令装到任意工作区：

```bash
npx github:ye0619/Shenlun-SKILL          # 从 GitHub 直接装（当前可用）
npx shenlun-skill                        # 发布到 npm 后可用
npx shenlun-skill --dir "D:\my-ws"       # 装到指定工作区（默认当前目录）
npx shenlun-skill --dry-run              # 只打印要做什么，不写盘
npx shenlun-skill --force                # 清空重建 skill 目录（清旧版本残留）
npx shenlun-skill --no-workspace         # 只装 skill，不建材料目录
npx shenlun-skill --help                 # 用法（--version 看版本）
```

装完你会得到：① `.dsh/skills/shenlun-judge/`（skill 本体）；② `工具/`（两个脚本）；
③ 五个材料目录 `真题/ 参考答案/ 作答记录/ 批改报告/ 批改规范/` 及各自的说明 README
（目录已存在就保留，README 已存在就不覆盖）。

装好以后，在支持 skill 的平台里打开这个工作区，直接说一句 `批改 2026河南县级` 就行。

### 克隆仓库手动用

```bash
git clone https://github.com/ye0619/Shenlun-SKILL.git
```

- 省事做法：**直接把这个仓库当工作区用**，材料往五个目录里放。
- 想装到别的工作区：把 `.dsh/skills/shenlun-judge/` 拷到目标工作区 `.dsh/skills/` 下，
  再把 `工具/` 两个脚本拷到目标工作区根目录。
- 注意：`.gitignore` 排除了那五个目录的内容，所以克隆下来它们是**空的**，得自己往里放材料。
  嫌麻烦就用上面的 npx。

### 为什么建议你照抄这套目录结构

1. **一次就能命中**：助手按 `{省份}/{卷ID}` 去五个目录找作答、答案、规范、历史报告；路径一致时一遍找齐。
2. **能自动归位、能横向对比**：命名规范了，报告才会自动登记进 `批改报告/README.md`，
   `-v2`／`-v3` 多稿和同省跨年份的卷子才能放在一起看趋势。
3. **结构乱了也不会崩，就是费来回**：材料散在根目录、名字含糊（`申论.pdf`、`答案.txt`）时，
   助手仍会归位，但要反复问你，token 和耐心都更费。

## 怎么用

**① 把材料丢进工作区**（丢根目录就行，不用自己摆）

助手批改前会自动认出**年份／省份／卷型／材料类型**，归到 `{材料类型}/{省份}/{卷ID}…` 并改名，
然后列一份"原路径 → 新路径"清单让你核对；名字含糊时会**先问你**，不擅自决定。

想自己放就按这个来：

- 作答 → `作答记录/{省份}/{卷ID}.txt`（**只收 md / txt**）。图片、扫描件**别放这儿**：
  助手会请你自己先转成文本（OCR 难免字误，字误直接影响采分点判定）；你说"先帮我转"才代转，
  并在报告里注明转写方式、附转写稿请你校对。
- 参考答案 → `参考答案/{省份}/{卷ID}/第N题.txt`，顺手在 `参考答案/README.md` 登记来源与年份。
- 该卷批改规范 → `批改规范/{省份}/`（`{卷ID}-批改规范.md` 或 `{卷ID}-大作文批改规范.md`）。
- 真题原卷 → `真题/{省份}/{卷ID}.pdf`；整理好的题面 → `真题/{省份}/{卷ID}.md`。

**② 说一句话**（越具体越准）

```
批改 2022河南乡镇                     # 助手自己去作答记录里找
批改 .\作答记录\河南\2022河南乡镇.txt   # 直接指文件，最省事
帮我批改这篇大作文，题目是"守正与创新"   # 文本贴在对话里
这道归纳概括我踩到采分点了吗
按这套卷的批改规范给我打分
倡议书格式怎么写  /  大作文立意和分论点怎么搞
展开  /  给我参考范文  /  导出 word
```

**③ 看报告**

每次批改 = 对话里一份精简报告 ＋ 自动落盘 `批改报告/{省份}/{卷ID}-批改报告.md`（重复批改用 `-v2`）。
报告里按这个顺序看：

1. **总分、建议区间和置信度**——分数只是个落点，别把它当结论；
2. **每题采分点核对**（哪些命中、哪些丢，都带原文证据）；
3. **"采分点共识表"**：标出这个点凭什么算分、是共识点还是低权点；
   机构都没写、但材料里确实有、且判定重要的点，**照样计分**，次要的才放"提醒区"；
4. **改进方向**——第一条就是本次最值钱的一条，先改它。

默认只给精简报告；说"展开／详细"才逐段逐句细评，要"参考范文"才出整篇示范。

## 省 token 的几个习惯

同样批一套卷，喂法不同能差好几倍：

| 习惯 | 为什么 |
|---|---|
| **一律用 `.txt` / `.md`** | 同样内容纯文本最省；docx 还得额外解压提取 |
| **图像先自己转文字** | 手写稿、扫描件自己敲一遍，比让模型 OCR 更省更准 |
| **材料放工作区，别贴进对话** | 题干材料放 `真题/`，说个卷ID，助手按需读 |
| **先给卷ID再批** | 一次定位题干、参考答案、规范、历史报告 |
| **一次一套卷或一题** | 一次丢五套＝让模型读五遍 |
| **参考答案整卷丢进目录** | 助手用脚本自动判"同源/独立"，你不用手工标 |
| **大作文只建一次刻度** | 范文梯队建一次缓存，之后只读画像，不重读范文 |
| **小题和大作文分开批** | 大作文最耗 token，不必每轮重跑全卷 |

## 配套插件：粉笔试卷批量下载

- **位置**：仓库根目录 `fenbi-pdf-downloader.user.js`（油猴单文件脚本）。

- **作用**：登录粉笔网页版后批量下载行测／申论试卷 PDF，下载的 PDF 可以直接当
  `真题/{省份}/{卷ID}.pdf` 用。

  在粉笔页面上正常浏览一次，再点"从抓包记录生成配置"。
- **提醒**：与粉笔官方无关，仅供个人学习自用，请遵守平台条款与版权规定。

## 目录与命名规范

五个材料目录**一律按省份分类**，文件统一用**卷ID**命名：**卷ID = `{四位年份}{省份}{卷型}`**
（如 `2022河南乡镇`、`2026国考行政执法`、`2024浙江A`）。

| 材料 | 规范路径 | 备注 |
|---|---|---|
| 作答 | `作答记录/{省份}/{卷ID}.txt` | 只收 md / txt；改稿用 `-v2`、`-v3`，不覆盖旧稿 |
| 参考答案 | `参考答案/{省份}/{卷ID}/第N题.txt` | 一题一文件；在 `参考答案/README.md` 登记来源与年份 |
| 批改规范 | `批改规范/{省份}/{卷ID}-批改规范.md`、`{卷ID}-大作文批改规范.md` | 该卷有就必须引用；自拟可用 `批改规范/_模板.md` |
| 真题原卷 | `真题/{省份}/{卷ID}.pdf` | 题面与材料的最高依据 |
| 真题题面 | `真题/{省份}/{卷ID}.md` | 整理一次长期复用 |
| 批改报告 | `批改报告/{省份}/{卷ID}-批改报告.md` | 助手自动落盘；登记表 `批改报告/README.md` |

- **命名含糊、年份或卷型冲突时，助手会先问你，绝不擅自猜**。
- 五个材料目录的内容不入库（只上传框架），克隆下来是空的。

## 移植到 Codex、Claude 等平台

skill 本体就是一堆 md 加两个标准库 Python 脚本，没有平台专属依赖，移植很轻。
思路：**`SKILL.md` 当系统提示挂进去，`references/` 当按需查的资料，`工具/` 当工具。**

**第一步：复制文件**
把 `.dsh/skills/shenlun-judge/` 整个目录拷到目标平台的工作区（目录名随意），
再把工作区根目录的 `工具/` 一并拷过去。（用 npx 也行。）

**第二步：接上入口提示**
按平台约定把主提示放到它认识的位置：

| 平台 | 入口 | 注意 |
|---|---|---|
| **Codex / Codex CLI** | 工作区 `AGENTS.md` | 沙箱默认只写工作区；脚本用 `python` 调；大批改建议分卷 |
| **Claude Code / Claude App** | `CLAUDE.md` 或 Skill 目录 | 长报告注意输出上限，可让报告分节写入再合并 |
| **Cursor / Windsurf** | `.cursor/rules/*.mdc`、`.windsurfrules` | 适合边写边批；长材料挤上下文，建议一次一题 |
| **ChatGPT 网页** | 首条消息粘 `SKILL.md` | 没有文件系统 → 字数只能估，**禁止标精确字数** |
| **纯本地脚本** | 任意 shell | 只需 `python`，无第三方依赖 |

入口提示写一句就够：**读 `skills/shenlun-judge/SKILL.md`，严格按其执行；输出必须带评分依据声明、
建议区间与置信度。**

**第三步：说明目录约定**
告诉它工作区里五个目录各是什么、卷ID 怎么组——本 README 的《目录与命名规范》可以直接当这段说明。

**移植时必须保住这六条（否则 skill 会退化）**

1. **题面要求最高**：L1（题干、大纲、考场规则）优先；模拟口径与参考口径必须标注"非官方"，
   不得说成官方标准。该卷有 `批改规范/` 就必须引用。
2. **不把参考答案当你的作答**：找不到作答就明说找不到，不许编、不许拿范文冒充。
3. **给分必须带建议区间和置信度**，不能只甩一个精确到小数点的数字。
4. **字数：核验是硬要求，且按口径计分**——示例答案／范文必须跑字数核验；
   你的作答超限按 `扣分 = ⌈超出达标上限的字数 ÷ 50⌉`（**向上取整**，"不超过 XX"上限＝XX、
   "XX 字左右"上限＝XX＋50）在报告里单列"⚠ 字数扣分"，**字数过少不扣**，
   且**只计"字数"这一项、不作降档理由**。别自创别的换算，也别写成官方罚则。
5. **大作文走"档位锚定 + 硬伤修正 + 档内定位"**，并保住三条禁令：
   同义表达与异构论证一律允许、具体案例不是采分点、"立意稍微模糊"不是硬伤。
6. **三条最容易被新版丢掉的用户口径**（改版／移植时务必一并搬走，否则口径会丢）：
   **① 数据与口语化表达不属采分点**（数字、月份、数量、百分比、口号式语句缺失不扣分）；
   **② 列举式带"等"的**（≥2 项）**任选一项即完整命中**，不必是第一项；
   **③ 采分点粒度按题型分化**——分析题从严（单点 ≤ 总分 15%），概括题·对策题从宽
   （单点 ≤ 总分 30%），公文维持 80/10/10。

## 脚本

- **`工具/count_chars.py`**（字数核验，答题卡口径：含标点、不含空格换行）
  ```bash
  python 工具/count_chars.py 答案.txt --limit 300            # 单块
  python 工具/count_chars.py 作答.txt --split --limits 300,250,400,450,1200   # 整卷切块
  python 工具/count_chars.py 作文.txt --floor 1000 --limit 1200               # 区间题
  python 工具/count_chars.py --selftest                      # 自检
  ```
  它和 Word 的字数统计不完全一致，报告统一以脚本值为准，别拿两个数字对比。
- **`工具/ref_independence.py`**（参考答案同源检测）：机构之间互相转抄很常见，
  所以"独立来源家数 = 分组数，不是文件数"；`--same 0.80` 判同源转抄，`--near 0.60` 判疑似同源。
  注意：**给分不用文本相似度**，这个脚本只用于参考答案之间判同源。
- **PDF 提取**（可选）：`python` + PyMuPDF（`import fitz`）。失败就换平台自带的 PDF／OCR 能力，并人工校对。

## 这套 skill 的不足

用之前请知道：

1. **没有官方标准可依**。官方阅卷细则与采分表通常不公开，档位区间、采分点拆分、扣分量级
   全是自建口径。它能保证"同一个人前后两次尺度一致"，**不能保证和考场给分一致**。
2. **分数是区间不是点**。主分只是落点，真正有用的是"建议区间 ＋ 置信度"。
3. **小题采分点可能重构偏差**。采分点是从材料里模拟拆的，与命题人的真实采分表可能多、少或错位；
   有参考答案的卷靠多口径交集纠偏，没有的偏差更大。
4. **公文三池比例没有官方依据**。内容/格式/语言各占多少分，官方从未公布，报告里的比例只是训练参照。
5. **大作文的"深刻""充实"仍是判断**。四维描述能对齐尺度，但不同判断者之间仍有 ±2 分左右的漂移——
   这也是建议区间存在的原因。
6. **反模板做得激进**。好处是不会因为没写五段三分被冤扣，代价是对"结构漂亮但内容空"的文章给分偏软。
7. **范文刻度是循环校准**。梯队参照档是同一个模型用同一套规则判出来的，只能当相对标尺，
   冲突时以题面＋四维实际表现为准。
8. **依赖你自己投喂材料**。`作答记录/`、`参考答案/`、`批改规范/` 都得你放；
   覆盖率不足的年份和卷型只能纯模拟，置信度上不去。
9. **PDF 提取有坑**。部分真题 PDF 文字层会乱码，需要换方式或 OCR，并人工校对。
10. **不会替你写整篇**。默认只给方向、采分点、示例答案（小题）与改进建议；要整篇范文得明确说。
11. **只覆盖申论**。行测、面试不在范围内。
12. **真题库要自己建**。题库不随 skill 分发，放在 `真题/{省份}/{卷ID}.md`；新环境默认没有，
    识别与匹配能力取决于你是否整理过。
