## 作者自述：这个 skill 是怎么来的

**前排提醒**：由于申论批改是一个巨大的黑箱，没有官方的答案和评分标准，所以只能依靠市面上的参考答案和评分标准模拟评分。所以很可能是在错误的答案上建立的错误标准，批改仅供参考。

我想尽可能去打造一套模板而不是一个确定的评分标准，项目内包含“真题”、“参考答案”、“批改规范”等，你可自行上传，也可以使用你认为可靠的批改规范，你还可以为每套真题自定义批改规范（文件不存在则使用默认），由此达到你认为可靠的批改效果。

**9.19 修改**：受阅卷流程启发——真实阅卷是先抽一批卷试批改，才定下评分标准。所以现在只要你上传了某套题的
参考答案，它批改前会先拿参考答案自己试批一遍、建立一个采分点共识，由此得出参考答案，然后再进行评分。对于大作文，它会先对参考范文进行定档，再拿你的作文和范文对比，不过在ds的评测下范文也只能是二类😋。


**9.22 修改**：修改给分过高的bug😋。从网上搜集了几份国考评分规范，据此重写了 skill。
感新月的建议，加进了 **MinerU**（把 pdf、docx、png、jpg 转成 md 的工具，本地也能部署：
https://github.com/opendatalab/MinerU ）。现在口径严格了，但还是很难完全模拟真人阅卷——
毕竟 AI 会把你每个字都过一遍，不漏过任何一个得分点。
同时将09年到26年的国考真题md文件上传。

**9.25 修改**：感谢1591kks的建议，根据他的评分标准进行了完善。

**一些碎碎念**：其实提高批改的准确率有个简单而直接的方法，就是搜集一批考场上的答案以及得分，如果数据足够大，便可以将部分作为训练集、部分作为测试集。但整个工程会耗费大量时间、精力和金钱，个人很难做好，可能机构有能力做吧。
如果你有多考几次的打算，便可以根据自己考场上的作答以及分数，对skill进行调试，但如果真这么做了说明当年没考上😂。

值得一提的是至少批改分数保持了高度一致性，在使用deepseek v4.1flash进行批改时，同一答案多次批改得分一致。在某试卷上deepseek v4.1flash和chatgpt 5.6sol分差在2分以内，这至少说明了skill具有一定约束性。还有就是经过几次修改，单次批改token消耗成功翻倍了😂。

**9.27 修改**：重新删去了字数计入评分。以下原因：为了节省token，以及提高批改准确率。目前批改是默认你已将手写答案提取成文档。这样ai统计字数会出现问题，比如“1.”会是2个字符，但它实际占1个格子；“2025”是4个字符，但实际占2个格子；因为标点不能出现在每行开头，所以和上一行最后一个字放在一个格子，诸如此类。我们可以通过设计一个复杂的计数办法，但会增加消耗的token，结果也可能不如人意。所以我删掉了字数统计，平时大家在格子纸上练习，字数应该会有把控。

此外每次批改完新开对话或有助于省token（未实测，这是ds爬取了几十次批改得出的结论），虽然单对话能让命中率提高，但发送大量上下文会导致额外大量的token消耗，而且是无意义的，在我今天的批改中发送上下文花费了0.76元。

上次修改完发现没有逻辑冲突直接提交了😂，当然这次同样没有实测，有问题大概明天发现。

最后离考试还有两个月，希望大家刷题的同时保持一定运动，用一个健康的身体迎接考试。

**10.3 修改**：修复了部分逻辑冲突。

**10.15 修改**：增加 Codex 入口与跨平台安装支持，精简重复规则，明确模型模拟评分的准确性边界。小题和公文的分点、顺序、层次、类别标签只作改进提醒，内容遗漏或错误仍按采分点判分。

**10.22 修改**：增加了 -10分模拟压分，彻底修复了评分过高的bug😋。
另外我把我搜集的真题、答案全部上传了，之前不上传怕可能有版权问题，如果有人找我我第一个删库跑路......
重要提示：经过我高强度蹬gpt 6.1 sol，不要用gpt的模型进行批改，效果被deepseek拉爆了，deepseek最新的flash模型批改的又快又便宜又好。

**10.23 修改**：用codex做了个壳子，如果你不会用agent可以试试，效果我没测试，虽然很不好意思，但我确实没测试，只是保证了壳子能跑通。
这个项目本来是打算当毕业设计做的，我最终的目标是打算把skill像搭积木一样可以随意拼接修改，但我感觉这个项目有点问题，所以就放弃了，未来可能再完善。

## 项目结构

```text
shenlun/
├── .agents/skills/shenlun-judge/  # Codex 发现入口（源码仓库转发到下方共用正文）
├── .dsh/skills/shenlun-judge/     # 共用 skill 源码，也是 dsh 原生入口
├── 真题/                           # 试卷原题：{省份}/{卷ID}.pdf + 整理好的 {省份}/{卷ID}.md
├── 参考答案/                       # 机构/真题参考答案：{省份}/{卷ID}/第N题.txt
├── 作答记录/                       # 你的作答（只收 md / txt）：{省份}/{卷ID}.txt
├── 批改报告/                       # 报告落盘：{省份}/{卷ID}-批改报告.md（+ 字数核验/共识表/刻度缓存）
├── 批改规范/                       # 某卷（尤其大作文）的批改规范：{省份}/{卷ID}-批改规范.md
├── 工具/                           # 配套脚本：卷面核验.py（整卷字数）、count_chars.py、split_reference.py、ref_independence.py
├── bin/install.js                  # npx 一键安装器
├── templates/workspace/            # 安装时写进新工作区的目录说明模板
├── fenbi-pdf-downloader.user.js    # 配套油猴脚本：粉笔试卷批量下载
└── package.json / README.md / LICENSE / .gitignore
```

**用途**

| 目录 | 放什么 | 谁放 |
|---|---|---|
| `作答记录/` | **你的作答**（批改对象），整卷一份或按题拆，**只收 md / txt** | 你 |
| `参考答案/` | 机构参考答案 / 真题参考答案，一题一文件 | 你收集，助手登记 |
| `批改规范/` | 某套卷的批改规范；批改该卷时**有就必须引用** | 你收集（或用助手试批改的草稿） |
| `批改报告/` | 报告母本；另存字数核验留痕、采分点共识表、大作文刻度缓存 | 助手自动落盘 |
| `真题/` | 原卷 PDF ＋ 整理好的 md（题面与材料是**最高依据**） | 你收集／助手整理 |
| `工具/` | `count_chars.py`、`ref_independence.py` | 随仓库发布，**路径固定，别改名** |
| `.agents/skills/shenlun-judge/`、`.dsh/skills/shenlun-judge/` | Codex / dsh 入口；共用正文与评分口径 | 本仓库维护 |

**Git 发布范围**（2026-10-23 更新）：

| 内容 | 是否入库 |
|---|---|
| `作答记录/`、`批改报告/` | 只上传 `.gitkeep` 与 `目录说明.md`；个人正文、得分、复盘和登记 `README.md` 留在本地 |
| `真题/`、`参考答案/`、`批改规范/` | 正常上传，包括各地区题面与原卷；含个人作答摘录或得分的规范单独忽略 |
| `desktop/` | 整个目录不上传，包含源码、依赖、安装包与验收产物 |
| `.shenlun-ui/`、本地会话、密钥与配置、日志和备份 | 不上传；额外私人文件放入 `.private/`、`私人资料/` 或 `隐私/` |
| `主界面展示.png`、`API配置.png` | 作为公开使用说明随 README 上传 |

公开材料中请保留来源信息，上传前移除个人批注、身份信息和密钥。`.gitignore` 按路径和文件名过滤，
不能自动识别正文中的隐私；已发现含私人批改内容的规范已列入单独忽略规则，清理后可移除对应规则。
两个个人目录中的 `README.md` 是本地登记文件，公开框架另见各自的 `目录说明.md`。

## 快速开始

### 桌面工作台（Windows，0.2.0）

需要可视化界面时，可使用独立的申论批改工作台。桌面工程和安装包保留在本地，
本仓库只展示用法与截图；克隆仓库或运行 npx 安装器不会得到桌面程序。
本地 0.2.0 安装包为 `desktop/release/Shenlun-Workbench-0.2.0-Setup.exe`。

1. 安装并启动程序，选择现有申论工作区或新建工作区。
2. 按年份、地区和卷型查找试卷，查看真题、参考答案、作答记录、批改规范与批改报告。
3. 五类 Markdown/TXT 资料均可编辑，保存前自动备份。参考答案通过新建文本或编辑已有文件维护，分数与想法直接写在正文旁；作答导入后按卷自动编号。
4. 在“API 与设置”填写服务地址、API Key 和模型名，可选择 DeepSeek 预设与深度思考开关。仅保存配置不会发起请求；“保存并测试”和实际批改会调用配置的服务，可能计费。
5. 在“Skill 管理”选择内置规则，或导入、复制和编辑自己的文档型 Skill；核对题目信息、作答版本与批改范围后开始批改，在“批改任务”查看进度和报告。

程序从本地工作区读取资料；连接测试和批改按所选 API 配置发送请求，参与批改的材料会发送给该服务。
密钥保存在应用用户数据目录，任务快照与备份位于工作区 `.shenlun-ui/`，均不纳入 Git。
当前参与批改仍需要文本，尚未接入 OCR、MinerU、Word/PDF 报告导出或云同步。

### 一键安装（npx）

本仓库自带一个零依赖安装器，一条命令装到任意工作区：

```bash
npx github:ye0619/Shenlun-SKILL          # 从 GitHub 直接装（当前可用）
npx shenlun-skill                        # 发布到 npm 后可用
npx shenlun-skill --dir "D:\my-ws"       # 装到指定工作区（默认当前目录）
npx shenlun-skill --harness codex        # 仅安装 Codex 入口与完整 skill
npx shenlun-skill --harness dsh          # 仅安装 dsh，保留原来的使用方式
npx shenlun-skill --dry-run              # 只打印要做什么，不写盘
npx shenlun-skill --force                # 清空重建 skill 目录（清旧版本残留）
npx shenlun-skill --no-workspace         # 只装 skill，不建材料目录
npx shenlun-skill --help                 # 用法（--version 看版本）
```

默认 `--harness all`。装完你会得到：① `.agents/skills/shenlun-judge/`（Codex）与
`.dsh/skills/shenlun-judge/`（dsh）；② `工具/`（配套 Python 脚本）；
③ 五个材料目录 `真题/ 参考答案/ 作答记录/ 批改报告/ 批改规范/` 及各自的说明 README
（目录已存在就保留，README 已存在就不覆盖）。

装好以后，在对应平台打开工作区，直接说 `批改 2026河南县级`；
Codex 也可显式调用 `$shenlun-judge`。若当前会话尚未发现新 skill，重新打开工作区或新建会话。

### 克隆仓库手动用

```bash
git clone https://github.com/ye0619/Shenlun-SKILL.git
```

- 省事做法：**直接把这个仓库当工作区用**，材料往五个目录里放。
- 想装到别的工作区：运行 `node bin/install.js --dir "目标工作区" --harness codex`（或 `dsh` / `all`）。
  手动复制时，把 `.dsh/skills/shenlun-judge/` **完整目录**放到目标 harness 的 skill 目录，
  再把整个 `工具/` 拷到目标工作区根目录；源码仓库的 Codex 转发入口不要单独复制走。
- 克隆仓库会得到已入库的真题、参考答案和不含隐私的批改规范；`作答记录/`、`批改报告/` 只有框架。
  npx 安装只分发 skill、工具和目录模板，题库与参考资料需另行复制或准备。

### 为什么建议你照抄这套目录结构

1. **一次就能命中**：助手按 `{省份}/{卷ID}` 去五个目录找作答、答案、规范、历史报告；路径一致时一遍找齐。
2. **能自动归位、能横向对比**：命名规范了，报告才会自动登记进 `批改报告/README.md`，
   `-v2`／`-v3` 多稿和同省跨年份的卷子才能放在一起看趋势。
3. **结构乱了也不会崩，就是费来回**：材料散在根目录、名字含糊（`申论.pdf`、`答案.txt`）时，
   助手仍会归位，但要反复问你，token 和耐心都更费。

## 怎么用

**① 把材料丢进工作区**（丢根目录就行，不用自己摆）

助手批改前会自动认出**年份／省份／卷型／材料类型**，归到 `{材料类型}/{省份}/{卷ID}…` 并改名，
然后列一份"原路径 → 新路径"清单让你核对；名字含糊时会**先问你**，不擅自决定。

想自己放就按这个来：

- 作答 → `作答记录/{省份}/{卷ID}.txt`（**只收 md / txt**）。图片、扫描件**别放这儿**：
  助手会请你自己先转成文本（OCR 难免字误，字误直接影响采分点判定）；你说"先帮我转"才代转，
  并在报告里注明转写方式、附转写稿请你校对。
- 参考答案 → `参考答案/{省份}/{卷ID}/第N题.txt`，顺手在 `参考答案/README.md` 登记来源与年份。
- 该卷批改规范 → `批改规范/{省份}/`（`{卷ID}-批改规范.md` 或 `{卷ID}-大作文批改规范.md`）。
- 真题原卷 → `真题/{省份}/{卷ID}.pdf`；整理好的题面 → `真题/{省份}/{卷ID}.md`。

**② 说一句话**（越具体越准）

```
批改 2022河南乡镇                     # 助手自己去作答记录里找
批改 .\作答记录\河南\2022河南乡镇.txt   # 直接指文件，最省事
帮我批改这篇大作文，题目是"守正与创新"   # 文本贴在对话里
这道归纳概括我踩到采分点了吗
按这套卷的批改规范给我打分
倡议书格式怎么写  /  大作文立意和分论点怎么搞
展开  /  给我参考范文  /  导出 word
```

**③ 看报告**

每次批改 = 对话里一份精简报告 ＋ 自动落盘 `批改报告/{省份}/{卷ID}-批改报告.md`（重复批改用 `-v2`）。
报告里按这个顺序看：

1. **总分、建议区间和置信度**——分数只是个落点，别把它当结论；
2. **每题采分点核对**（哪些命中、哪些丢，都带原文证据）；
3. **"采分点共识表"**：标出这个点凭什么算分、是共识点还是低权点；
   机构都没写、但材料里确实有、且判定重要的点，**照样计分**，次要的才放"提醒区"；
4. **改进方向**——第一条就是本次最值钱的一条，先改它。

> 报告里还会有一行 **"⚠ 字数提示"**：题面有字数要求时助手会核验你达标没有，**但这一项不扣分**
> （2026-09-27 起字数不计入评分），它只是提醒你考场上的字数风险，压缩建议会一并给。

默认只给精简报告；说"展开／详细"才逐段逐句细评。大作文报告会附一篇本卷已收录的示例范文，
从模拟档位最高者中选取并原样展示，注明来源、字数、模拟档位和选取理由；没有可用范文时注明“未收录”。
完整国考整卷汇总施加一次 −10 分模拟压分修正（最低 0 分），同时列出压分前合计；单题分数保持原值。
单题、缺题、省考不适用，用户明确要求不压分时按用户要求执行。这是训练口径，不代表官方算法。

## 省 token 的几个习惯

同样批一套卷，喂法不同能差好几倍。

**先说实测**（2026-09-27 拿另一段真实批改对话的 365 次请求逐轮对账）：批 9 份卷花 **¥6.87**，
其中 **49% 的钱花在"每一步把整个上下文重发一遍"**（不是读文件贵）；每步平均上下文从第 1 卷的
31k tokens 一路涨到第 9 卷的 **762k**；单卷最贵 ¥1.65，便宜时 ¥0.45。所以**最省的动作是"别让上下文变长"**。

| 习惯 | 为什么 |
|---|---|
| **一卷一会话**（第一优先） | 跨卷批改会让每步上下文翻倍——实测 9 卷时单步 762k tokens。批完一卷就新开对话，成本能压回约 1/3，也彻底避免"上一卷的采分点串到这一卷"；顺手避开上下文塞满后整份重发（每次约 ¥0.78） |
| **每件事只让助手调一次脚本** | 整卷字数用 `工具/卷面核验.py`、拆题用 `工具/split_reference.py`、同源用 `ref_independence.py`。过去一次批改会写十几个临时文件、反复跑脚本再回读，光这一项就多花十几步 |
| **别让助手整读大文件** | `references/` 里有 119 KB 的表；助手应切片查。登记类写入已用 README 锚点，不会为了加一行登记把整份 README 读一遍 |
| **一律用 `.txt` / `.md`** | 同样内容纯文本最省；docx 还得额外解压提取 |
| **图像先自己转文字** | 手写稿、扫描件自己敲一遍，比让模型 OCR 更省更准 |
| **材料放工作区，别贴进对话** | 题干材料放 `真题/`，说个卷ID，助手按需读 |
| **先给卷ID再批** | 一次定位题干、参考答案、规范、历史报告 |
| **一次一套卷或一题** | 一次丢五套＝让模型读五遍 |
| **参考答案整卷丢进目录** | 助手用脚本自动判"同源/独立"，你不用手工标 |
| **大作文只建一次刻度** | 范文梯队建一次缓存，之后只读画像，不重读范文 |
| **小题和大作文分开批** | 大作文最耗 token，不必每轮重跑全卷 |

> 几句提醒：**输出也是钱**（占实测账单的 42%），所以"展开／详细"这类要求本身就在加钱；
> 中间产物（规范、共识表、画像）现在都收敛成"整卷一份"，报告里只留结论，不再复制一遍缓存。

## 目录与命名规范

五个材料目录**一律按省份分类**，文件统一用**卷ID**命名：**卷ID = `{四位年份}{省份}{卷型}`**
（如 `2022河南乡镇`、`2026国考行政执法`、`2024浙江A`）。

| 材料 | 规范路径 | 备注 |
|---|---|---|
| 作答 | `作答记录/{省份}/{卷ID}.txt` | 只收 md / txt；改稿用 `-v2`、`-v3`，不覆盖旧稿 |
| 参考答案 | `参考答案/{省份}/{卷ID}/第N题.txt` | 一题一文件；在 `参考答案/README.md` 登记来源与年份 |
| 批改规范 | `批改规范/{省份}/{卷ID}-批改规范.md`、`{卷ID}-大作文批改规范.md` | 该卷有就必须引用；自拟可用 `批改规范/_模板.md` |

| 真题题面 | `真题/{省份}/{卷ID}.md` | 整理一次长期复用 |

- 五个材料目录的内容不入库（只上传框架），克隆下来是空的。

## 移植到 Codex、Claude 等平台

skill 本体使用通用 `SKILL.md` 元数据与 Markdown，配套脚本只依赖 Python 3 标准库。
它是按任务加载的指导，不需要把全部评分规则放进系统提示或 `AGENTS.md`。

**第一步：复制文件**
Codex / dsh 推荐用安装器：`node bin/install.js --dir "目标工作区" --harness all`。
两边从同一份 `.dsh/skills/shenlun-judge/` 源码生成完整 skill；已有个人材料与登记不会被覆盖。
直接使用本源码仓库时，Codex 的入口仅转发到共用正文；安装器会跳过源码自身复制，
即使加 `--force` 也不会删除源 skill 或 `工具/`。

**第二步：接上入口提示**
按平台约定把主提示放到它认识的位置：

| 平台 | 入口 | 注意 |
|---|---|---|
| **Codex / Codex CLI** | `.agents/skills/shenlun-judge/SKILL.md` | 自然语言或 `$shenlun-judge` 调用；不改 `AGENTS.md`；在材料工作区运行脚本 |
| **DeepSeek Harness（dsh）** | `.dsh/skills/shenlun-judge/SKILL.md` | 保留 filesystem skill provider 的发现方式与自然语言调用 |
| **Claude Code / Claude App** | `CLAUDE.md` 或 Skill 目录 | 长报告注意输出上限，可让报告分节写入再合并 |
| **Cursor / Windsurf** | `.cursor/rules/*.mdc`、`.windsurfrules` | 适合边写边批；长材料挤上下文，建议一次一题 |
| **ChatGPT 网页** | 提供 `SKILL.md` 与所需 references | 没有执行工具时注明未做字数/同源核验，不输出虚构精确字数或独立来源数 |
| **纯本地脚本** | 任意 shell | 只需 `python`，无第三方依赖 |

其他平台手动接入时，把共用 skill 目录与 `工具/` 完整复制过去。入口提示指向实际路径：
**读所安装的 `shenlun-judge/SKILL.md`，按其执行；输出必须带评分依据声明、
建议区间与置信度。**

路径、解释器选择、可选 MinerU、无联网/无写入/无脚本时的处理，统一见
[运行环境兼容约定](.dsh/skills/shenlun-judge/references/runtime-compatibility.md)。
`references/` 相对于 skill 目录，材料与 `工具/` 相对于用户工作区；
MinerU 优先复用已有安装，不因一次批改自动修改全局 skill 或记忆。

**第三步：说明目录约定**
告诉它工作区里五个目录各是什么、卷ID 怎么组——本 README 的《目录与命名规范》可以直接当这段说明。

**移植时必须保住这六条（否则 skill 会退化）**

1. **题面要求最高**：L1（题干、大纲、考场规则）优先；模拟口径与参考口径必须标注"非官方"，
   不得说成官方标准。该卷有 `批改规范/` 就必须引用。
2. **不把参考答案当你的作答**：找不到作答就明说找不到，不许编、不许拿范文冒充。
3. **给分必须带建议区间和置信度**，不能只甩一个精确到小数点的数字。
4. **字数：核验是硬要求，但不计入评分**——示例答案／范文必须跑字数核验（并落在 85%–95%）；
   你的作答**只判"合不合题干要求"**（"不超过 XX"＝上限 XX；"XX 字左右"＝XX±50），
   超限/偏少只在报告里单列一句"⚠ 字数提示"，**不扣分、不降档、不进任何分值**；压缩建议照给。
   别自创扣分公式（`⌈超出达标上限 ÷ 50⌉` 那套已于 2026-09-27 废止）。
5. **大作文走"档位锚定 + 硬伤修正 + 档内定位"**，并保住三条禁令：
   同义表达与异构论证一律允许、具体案例不是采分点、"立意稍微模糊"不是硬伤。
6. **四条最容易被新版丢掉的用户口径**（改版／移植时务必一并搬走，否则口径会丢）：
   **① 字数不计入评分**——题干要求须核验，但超限/偏少只提示，不扣分、不降档；
   **② 数据与口语化表达不属采分点**（数字、月份、数量、百分比、口号式语句缺失不扣分）；
   **③ 列举式带"等"的**（≥2 项）**任选一项即完整命中**，不必是第一项；
   **④ 采分点粒度按题型分化**——分析题从严（单点 ≤ 总分 15%），概括题·对策题从宽
   （单点 ≤ 总分 30%），公文维持 80/10/10。

## 脚本

四个 Python 3 标准库脚本，各带 `--selftest`：

- **`工具/卷面核验.py`**（**整卷字数一次过**——批改用户作答就用它）
  ```bash
  python 工具/卷面核验.py 作答记录/浙江/2019浙江A.txt --spec "1:300,2:300,3:300,4:approx1000"
  python 工具/卷面核验.py 作答.txt --spec "1:300,2:approx1000,3:1000-1200,4:min800" --md out.md
  python 工具/卷面核验.py --selftest
  ```
  一次出 ASCII 表格（控制台不会乱码），`--md` 直接写出报告用的中文块。
  `--spec` 语法：`N:300`＝不超过、`N:approx1000`＝1000 字左右（**±50**）、`N:1000-1200`＝区间、`N:min800`＝不少于。
  **字数不计入评分**（2026-09-27）：超限只作提示，不扣分、不降档。
- **`工具/count_chars.py`**（单块字数，答题卡口径：含标点、不含空格换行）
  ```bash
  python 工具/count_chars.py 答案.txt --limit 300            # 示例答案
  python 工具/count_chars.py 作文.txt --limit 1000 --approx  # "1000 字左右"（±50）
  python 工具/count_chars.py --selftest
  ```
  它和 Word 的字数统计不完全一致，报告统一以脚本值为准，别拿两个数字对比。
- **`工具/split_reference.py`**（**参考答案汇总件按题拆分**）
  ```bash
  python 工具/split_reference.py "参考答案/浙江/2026浙江B/.原始件/x.md" --outdir "参考答案/浙江/2026浙江B" --dry-run
  ```
  只新增、正文一字不改、不动源件；已存在默认跳过。**别再为拆题现写临时脚本**。
- **`工具/ref_independence.py`**（参考答案同源检测）：机构之间互相转抄很常见，
  所以"独立来源家数 = 分组数，不是文件数"；`--same 0.80` 判同源转抄，`--near 0.60` 判疑似同源。
  注意：**给分不用文本相似度**，这个脚本只用于参考答案之间判同源。
- **PDF 提取**（可选）：`python` + PyMuPDF（`import fitz`）。失败就换平台自带的 PDF／OCR 能力，并人工校对。
- **省 token 纪律**：每件事**只调一次**——整卷字数用 `卷面核验.py`、拆题用 `split_reference.py`、
  家数用 `ref_independence.py`；不写临时 `_*.txt` 再回读、不为一次性任务现写脚本、不整篇读大的 `references/`。

## 这套 skill 的不足

用之前请知道：

1. **没有官方标准可依**。官方阅卷细则与采分表通常不公开，档位区间、采分点拆分、扣分量级
   全是自建口径。它能保证"同一个人前后两次尺度一致"，**不能保证和考场给分一致**。
2. **分数是区间不是点**。主分只是落点，真正有用的是"建议区间 ＋ 置信度"。
3. **小题采分点可能重构偏差**。采分点是从材料里模拟拆的，与命题人的真实采分表可能多、少或错位；
   有参考答案的卷靠多口径交集纠偏，没有的偏差更大。
4. **公文三池比例没有官方依据**。内容/格式/语言各占多少分，官方从未公布，报告里的比例只是训练参照。
5. **大作文的"深刻""充实"仍是判断**。四维描述能对齐尺度，但不同判断者之间仍有 ±2 分左右的漂移——
   这也是建议区间存在的原因。
6. **反模板做得激进**。好处是不会因为没写五段三分被冤扣，代价是对"结构漂亮但内容空"的文章给分偏软。
7. **范文刻度是循环校准**。梯队参照档是同一个模型用同一套规则判出来的，只能当相对标尺，
   冲突时以题面＋四维实际表现为准。
8. **依赖材料覆盖**。个人作答需要自己准备；仓库已有参考答案和规范不能覆盖所有年份、地区与卷型，
   缺少对应材料时仍需补充，覆盖不足会限制判断依据。
9. **PDF 提取有坑**。部分真题 PDF 文字层会乱码，需要换方式或 OCR，并人工校对。
10. **范文依赖已有收录**。大作文报告展示的是本卷已收录范文，没有时不会编造来源或冒充机构范文。
11. **只覆盖申论**。行测、面试不在范围内。
12. **安装方式影响题库范围**。克隆仓库包含已入库材料；npx 安装仅提供 skill、工具与目录模板，
    需另行准备 `真题/{省份}/{卷ID}.md`，识别与匹配能力取决于资料覆盖与命名。
