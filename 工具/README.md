# 工具/

这个目录放 **skill 的配套脚本**（skill 的文档按**固定路径**调用它们，**请不要改名或移动**）：

| 脚本 | 干什么 | 典型命令 |
|---|---|---|
| `count_chars.py` | **单块字数统计**（答题卡口径：含标点，不含空格换行）。**示例答案/参考范文的标注字数必须由它产出** | `python 工具/count_chars.py 作文.txt --limit 1000 --approx` |
| **`卷面核验.py`** | **整卷字数一次过核验**（把整份作答按题切块 → 一屏 ASCII 表格 → 达标/超限判定）。**批改用户作答时用这个，不要再用"写临时文件＋反复跑 count_chars"那套** | `python 工具/卷面核验.py 作答记录/浙江/2019浙江A.txt --spec "1:300,2:300,3:300,4:approx1000" --md 批改报告/.字数核验/2019浙江A-字数.md` |
| **`split_reference.py`** | **参考答案汇总件按题拆分**（一次调用切出 `第N题.txt`；**只新增、不动源件**，已存在默认跳过） | `python 工具/split_reference.py "参考答案/浙江/2026浙江B/.原始件/x.md" --outdir "参考答案/浙江/2026浙江B"` |
| `ref_independence.py` | **参考答案同源检测**：对同一题的多个参考答案两两算文本重合率并分组，输出**独立来源家数**（＝分组数），供"小题采分点共识模型"判"几家独立" | `python 工具/ref_independence.py 参考答案/河南/2022河南乡镇 --question 1` |

- 四个脚本都是 **Python 3 标准库实现、零第三方依赖**，各带 `--selftest` 自检：
  `python 工具/count_chars.py --selftest`、`python 工具/卷面核验.py --selftest`、
  `python 工具/split_reference.py --selftest`、`python 工具/ref_independence.py --selftest`。
- **省 token 纪律（2026-09-27 实测后新增）**：这三件事**各只允许一次调用**——
  整卷字数 → `卷面核验.py`（一次出表，`--md` 直接产出报告块）；
  汇总件拆题 → `split_reference.py`；同源家数 → `ref_independence.py`。
  **禁止**写 `.dsh/_*.txt` 临时件再回读、**禁止**为一次拆分现写 `.py` 脚本
  （历史实测：单卷因此多花 ≈12 步、约 1.5 万 output tokens）。
- **控制台中文会乱码**：`卷面核验.py` / `split_reference.py` 的屏幕输出**刻意只用 ASCII**
  （写进文件的中文走 `--md`）；`count_chars.py` 的结论行含中文，若显示乱码，
  加 `--json` 读结构化结果，不要靠"再跑一遍"来确认。
- **口径纪律**：`ref_independence.py` 的相似度**只用于参考答案之间判同源**，
  **不参与给分**（给分看语义，不看文本相似度）；阈值 `--same 0.80` / `--near 0.60` 属经验口径。
- **诊断参数清单**（与 `SKILL.md` 第十节索引一致）：`--question`／`--same`／`--near`／
  `--min-chars`／`--json`／`--quiet`／`--no-split`／`--sensitivity`／`--no-autojunk`／`--selftest`。
- **本步只是"初值"**：家数是**阶段 A 试批改的输入**，不是最终结论——
  逐份试批改后若发现某点"实际有 1–2 家写了"（而速判记成 0 家），
  **以试批改结论为准**并更正共识表（判定与定价见 `small-questions.md` 第四节阶段 A）。
- **家数采信条件（硬性）**："独立来源家数"只有在**同时跑了 `--sensitivity`**、
  **输出无 ⚠ 告警**、且**临界相似度（0.55–0.65）与长度离群（字数比 >3 倍）已人工复核**时，
  才可直接采信；否则一律按 `small-questions.md` 第四节第 3 节的**四条复核硬规则**
  人工复核后登记，**不得只抄一个家数**。
- **三条已知边界**（判读结论时必须知悉）：
  1. **`SequenceMatcher` 的长度稀释**：短文本照抄长原文时 ratio 会被长度拉低
     （100 字节选照抄 1000 字原文，ratio 可能只有 0.18）→ 可能把同源判成"独立"，
     须人工复核字数比；
  2. **并查集传递串联**：A≈B、B≈C 会把 A、C 并入同组（即使 A 与 C 并不像），
     组会越滚越大 → 家数可能少算，临界情形须跑 `--sensitivity` 看稳定性；
  3. **`autojunk` 对长文本的影响**：difflib 默认把长文本中的高频字符当"垃圾元素"，
     长文本相似度可能被推高或压低 → 用 `--no-autojunk` 交叉验证结论稳不稳。
- **脚本不可用时不得主张共识点**：`工具/ref_independence.py` 跑不了（Python 缺失／
  `工具/` 被删）→ 视为**未完成同源判定**：**本题不主张任何共识点**，所有采分点按
  "**家数未定的低权点**"处理（**报告中不得写成"0 家收录"**——家数根本未知），
  **按低权计分**（适用"参考资料不完整"例外条，不能拿"0 家"当真），
  **置信度上限"低"**，报告须写明"未做同源检测（原因：…）"。
- **切分口径的两条硬规则（2026-09 修订，修正两处实测误判）**：
  1. **H1（`# …`）不认白名单外的名字**：参考答案文件里 H1 通常是**范文/公文标题**
     （如 `# 做隐形冠军`），一旦误认，就会把整篇范文切成两个条目、并让紧随其后的机构名
     变成"0 字空条目"。机构标签的惯例是 H2–H6（`## 粉笔`／`### 站长`）；
     **H1 只认括号包裹的未知名字**（`# 【先声夺人】`）。实测：2018 浙江 A 第 3 题
     原报"3 家 + 1 空条目"，修正后为 **5 家**。
  2. **剥掉"另一份答案"式的尾部括号限定**：`中公（参考答案 1）`＝`中公`、`华图【答案二】`＝`华图`；
     但 `粉笔（某笔）` 这类**别名不剥**（那是另一条产品线）。实测：同上题，
     两条中公答案原被并成 1 条，修正后各计 1 家。
  ⚠ 若你的答案文件用 `# 粉笔` 这种 H1 写机构名，请改成 `## 粉笔`（或用 `--no-split`）。
  自检含**回归用例**（`--selftest` 的"自检10"专测这两条），共 10 项。
- 用 `npx` 安装时，安装器会自动把本目录放到你工作区的 `工具/` 下；
  清空或删掉本目录会导致"字数核验""同源检测""汇总件拆题"不可用（重新安装即可恢复）。
- 你可以打开这几个脚本查看逻辑，也欢迎按自己的需要改；但改了以后记得同步 `README.md` 里
  对命令的说明（`.dsh/skills/shenlun-judge/references/word-count.md`、
  `references/reference-answers.md` 与 `references/small-questions.md` 第四节都引用了这里的命令）。

## `lint_rulings.py`（**维护用**：已废止口径残留检查）

> ⚠ 本节这个脚本**不是**批改流程的四个配套脚本之一，**skill 文档不调用它**，也不参与批改；
> 它是 **skill 维护工具**（体检报告 2026-10-03 第六节第 3 条提出）。

**用途**：改完 skill 后跑一次，检出**已废止口径特征串的残留**（例如旧字数弹性"±10%"、
旧三池比例"60–70"、旧"0 家点三层口径"、旧分值池取值"3＋3＋4"、过期体积标注"119 KB"……），
把过去靠人工专项写《冲突检测报告》的做法变成**一条命令的例行检查**。

**用法**：

```bash
python 工具/lint_rulings.py                        # 扫默认三处：skill 本体 / templates/workspace / 批改规范
python 工具/lint_rulings.py --root <目录>           # 只扫指定目录（可多次指定，覆盖默认）
python 工具/lint_rulings.py --show-suppressed      # 连"废止说明上下文"里的命中也列出来
python 工具/lint_rulings.py --json                 # 机器可读（落盘留痕）
python 工具/lint_rulings.py --selftest             # 自检
```

- **扫描范围**：`--root` 指定的目录（默认：`.dsh/skills/shenlun-judge`、`templates/workspace`、
  `批改规范`，**存在才扫**），递归、只扫 `*.md`。
- **允许上下文（自动忽略，共四类）**——命中记为**已忽略**（默认不报、不计入残留数）：
  1. 命中行**本身或它的前一行**含
     `已废｜废止｜⛔｜~~｜修订记录｜补注｜修正｜历史｜旧口径｜被取代｜2026-09-19｜2026-09-22｜2026-09-25｜2026-09-27`
     （`~~` 计入：Markdown 删除线＝该段被废止）；
  2. 命中行的**后 1–3 行**含 `补注｜修正`（例：紧跟其后的"（2026-10-03 补注：…）"）；
  3. 命中行含"旧→新"对照（`→`）且其**紧邻上一段**是 `**2026-xx-xx …修订…**` 批次标题
     （中间最多隔 2 个空行）——只认这种极窄形态：**光有批次标题不豁免，仍须本行含 `→` 对照**，
     且不许跨正文段落；
  4. **误报豁免（负向上下文，只作用于 L05／L11）**：命中行本身就是在**禁止这件事**
     （含 `不得再写｜禁止｜不得｜禁用话术｜⛔`）或**描述性/引用性**地使用该旧措辞
     （含 `不空喊口号｜正面描述｜描述性用法｜解释性引用｜引用性`）时不报——
     真残留行内没有这些标志（如 `不合格＝空喊口号、…`），照旧报出。
- **输出**：`<相对路径>:<行号>: [L07] <说明> :: <行内容（截断 100 字符）>`，
  结尾一行统计 `残留 N 项；已忽略（废止说明／误报豁免）M 项`；
  `--show-suppressed` 时每条忽略项后附**忽略理由**（如 `<忽略：后 2 行注记（「补注」）>`）。
- **`--json`**：`residues`／`suppressed`／`counts`／`roots` 与条目键
  （`file`／`line`／`rule`／`desc`／`text`／`suppressed_by`）**保持不变**；
  `suppressed` 条目**新增** `reason`（一句话说明为何忽略）。
- **`--selftest`**：**23 项**回归，逐项打印 `OK｜FAIL`——规则命中、本行/前一行/后 1–3 行忽略、
  `~~` 删除线、批次标题＋旧→新对照、L05／L11 负向豁免、**真残留必须报出**（两条 L11 ＋ 一条 L05），
  外加三条"不得过度豁免"的反向控制项（批次标题无 `→`、`→` 无批次标题、后 3 行无注记）。

**退出码**：`0` ＝ 无残留；`1` ＝ **有残留**（需人工确认：这些旧句是否缺少废止标注）；
`2` ＝ 参数错误。

**什么时候跑**：① **每次修订 skill／templates 之后**（提交前）；② 发布 npm 包前；
③ 排查"某处口径不一致"时先跑一遍缩小范围。**有残留不等于错**——先看它是否只是缺少废止标注，
确认是真残留再改写为现行口径。

**现行规则表（11 条）**：

| id | 特征串 | 说明 |
|---|---|---|
| L01 | `±10%` | 旧字数弹性（现为"X 字左右"±50） |
| L02 | `⌈超出` | 旧字数扣分公式（2026-09-27 已废） |
| L03 | `60–70` | 旧公文三池比例（现为 内容 80%／格式 10%／语言 10%） |
| L04 | `分三层` | 旧"0 家点三层口径"（现为"先判重要性"） |
| L05 | `0 家一律` | 旧"0 家一律不计分／一律进提醒区" |
| L06 | `两个配套脚本`／`配套脚本只有`／``只有 `count_chars` 与`` | 旧脚本数（实为 4 个） |
| L07 | `3＋3＋4` | 旧分值池取值（10 分/3 点＝40%，已废） |
| L08 | `每点 ≥3 点` | 误述（实文为"每题至少 3 个点"） |
| L09 | `119 KB`／`61 KB` | 过期体积标注（现为 140 KB／70 KB） |
| L10 | `(?<!通用)点数可行区间` | 旧措辞（现为"通用可行区间 3 ≤ N ≤ 10"） |
| L11 | `空喊口号` | 旧示例措辞（现为"通篇空泛表态而无事实/机制/论证支撑"） |

> 规则表写在脚本顶部的 `RULES` 里：**改了口径就往里加一条**（id／正则／一句说明），
> 与 `README.md` 这张表同步即可；**不要改脚本的调用方式**（skill 维护流程按固定命令调用）。
